# 知识侠客（Pixel Flashcard RPG）

把间隔重复（SM-2）复习包装成回合制卡牌战斗的**本地优先单机游戏**：答对一张卡就造成一次伤害，
打穿一个知识领域的"卷灵"Boss，把学过的知识变成角色的等级与六维。纯前端、无后端、无账号——
因此进度的唯一保全手段是**导出 JSON 备份**，离线也能玩。

## 现在就能玩

**手机浏览器直接打开：<https://luyangk.github.io/pixel-flashcard-rpg/>**
（GitHub Pages，main 分支推送后自动发布。）

想当 App 用：见下面的「装到主屏」。装好后从图标启动是全屏无地址栏的，
而且**第二次打开不需要联网**（Service Worker 会把页面、脚本、样式与全部素材缓存下来；
存档一直在本机 IndexedDB，从不上传）。首次打开建议连着 Wi-Fi 等它加载完再看一眼。

### 装到主屏（Android Chrome，四步）

1. **Chrome** 打开 <https://luyangk.github.io/pixel-flashcard-rpg/>，等游戏进到菜单（素材要下载完）；
2. 点右上角 **⋮** 菜单 → **「安装应用」**（有的版本写「添加到主屏幕」/「安装」）；
3. 弹窗里确认「安装」——主屏上会出现一张**闪卡图标**（墨底、折角宣纸、朱砂印），
   和普通 App 一样能拖进文件夹、进最近任务；
4. 之后从**主屏图标**打开：全屏无地址栏；断网也能开；「分享 → 知识侠客」也会出现在
   微信/浏览器的分享面板里（这是 `share_target`，**只有真正装成应用才有**）。

### 怎么更新（以及怎么确认自己更新了）

**不用你做什么**：更新全在网页层，主屏图标只是个壳。发版后**重新打开一次**（或连着网下拉刷新）就是新版
—— 正在打的那一局不会被自动刷新，所以它会停在旧版直到你自己刷。

三点要知道的：

- GitHub Pages 给 `index.html`/`sw.js` 都发 `cache-control: max-age=600`，所以**刚发版 10 分钟内**刷新
  可能还是旧页；**等十来分钟再打开**就一定是新版；
- 断网时打开的是缓存里的旧页（离线可用的代价，属正常）；
- ⚠️ **别用"清除站点数据/清除并重置"来催更新** —— 那会连 IndexedDB 里的存档一起删掉。真要做任何清数据
  操作，先在「设置 → 存档 → 导出备份」。其实你不需要：重新打开就够。

**「设置 → 关于」**里有**当前版本**（就是构建戳，与离线缓存名同源）与**「检查更新」**按钮：查完若发现新版，
会提示你并出现**「立即更新」**（点了才重新加载页面 —— 不会在你打一半时突然刷新）。

几点如实说明：

- **点了「安装」提示"正在安装"、之后就没了、主屏也找不到图标？** 这不是游戏的问题，是**网络**：
  安卓上"装成应用"的实质是 Chrome 请 **Google 的 WebAPK 铸造服务器**（`webapks.google.com`）
  现铸一个 APK 交给 Play 服务安装。**到不了 Google 的网络下（中国大陆直连就是），这一步必然失败**，
  而且失败得很安静 —— 提示消失、没有图标、搜不到（现场实测：设备上确实没有 `org.chromium.webapk.*` 包，
  且 `webapks.google.com` / `www.google.com` / `play.google.com` 三个域名全部不可达）。两条出路：
  1. **挂上能到 Google 的网络**（代理/梯子）再点一次「安装应用」——能通就装成真应用（全屏 + 分享入口）；
  2. **不装也能玩**：把上面那个网址存成书签（或留在 Chrome 标签里），**离线照常打开**
     —— 离线靠的是 Service Worker，与"装不装"无关；也可以用系统的「浏览器」App 打开后选
     「添加到桌面」，那是个不经过 Google 的快捷方式（图标会在主屏，但点开是带地址栏的窗口，
     **没有**系统分享入口）。分享进来那条路在没有真应用时请走"复制链接 → 采新卡里粘贴"。
- **为什么菜单里写的是"安装应用"而不是"添加到主屏幕"**：只有**图标齐备**（至少一张 192×192）
  时 Chrome 才把它当**应用**装（WebAPK）；图标不达标时 Chrome 只给一个**书签快捷方式**，
  那样**不会有分享入口**。2026-09 之前本作的清单只声明了 32×32/64×64，正好踩这个坑
  （现场实测：清单里的图标按 `/bundle/assets/...` 解析 ⇒ 404），现已补齐 192/512/maskable 三张（D51）。
- 小米/华为等国产 ROM 的 Chrome 菜单文案略有差异，找带**安装**字样的那一项（不是"添加书签"）。
- **iOS Safari 装不了分享入口**：iOS 的 PWA 不支持 `share_target`，只能"添加到主屏幕"当全屏网页用；
  采新卡在 iPhone 上请走"复制链接 → 在采新卡里粘贴"这条路。
- 桌面 Chrome / Edge 地址栏右侧也有安装图标（⊕ / 显示器图标），效果相同。

技术底座是四层分离：`src/core/` 纯 TypeScript 逻辑核（零 DOM、零平台 API、时间与随机全部入参化）、
`src/platform/` 平台能力抽象（IndexedDB / 内存存储、时钟、时区、随机播种、图片与文件口）、
`src/app/` 编排层（会话控制器、Boss 净化、预置内容种子、导入导出）、`src/ui/` + `src/stage/`
（原生 DOM 屏组件与 Canvas 战斗舞台，无框架、无游戏引擎）。

## 玩一局（本地调试）

> 手机上最省事的是直接用上面的线上地址；下面这套是**改代码时**用的。
> 注意 dev server **不会**注册 Service Worker（`import.meta.env.PROD` 才注册），
> 所以本机改一行立刻见效，不会被离线缓存挡住。

```bash
npm install                       # 首次；/sdcard（noexec）上还需 node scripts/link-native-bindings.mjs
npm run dev -- --host 127.0.0.1   # 只在本机浏览器打开 http://127.0.0.1:5173
# 想在**手机**上玩：绑到局域网，然后用手机浏览器访问 http://<电脑局域网IP>:5173
npm run dev -- --host 0.0.0.0
```

首次启动会自动灌入 4 个预置领域（成语典故 / 英语词根 / 生活常识 / 唐诗，共 30 张手写卡）。
**玩法要点**：伤害跟着"背熟程度"走——`new` 每击 `atk × 0.3`（三成）、`learning` ×0.7、
`review` ×1.0、`mastered` ×1.5。所以循环是：背卡 → 稳定度晋升 → 每击伤害翻倍 → 打赢遭遇战攒经验升级
→ 回头挑战卷灵 Boss。战败不是白输：败局会演出"假记忆注入"（LORE §5.5，纯演出、零数值后果）。

### 怎么作答（v2.6 起：不再靠"我觉得我记住了"）

- **选择题（默认）**：正面 + 4 个选项（1 正确 + 3 干扰）。选中即判分 ——
  **答对 = 记住了，答错 = 记错了**。干扰项由模型在**生成这张卡时**一并产出并随卡保存，
  所以复习出题**不会再消耗你的 AI 额度**。
- **直接看答案**：不想答就点它。**记为答错**（没回忆就记正分，等于把"全靠自觉"的漏洞留着）。
- **其实我是猜的**：答对之后有个不显眼的小按钮，点了把这次改判为答错（4 选 1 有 25% 蒙对率）。
- **问答模式**：在设置里切（战斗屏右下角也能本局切换）。你用一句话写自己的理解，
  由你的 AI 判断是否与答案一致，并告诉你**差在哪个要点**上。
- 三者都遵守同一条铁律：**作答之后先展开完整答案**，再由你点「继续」进入下一张。

代价如实说：选项只发「对/错」两档，原本的「太简单 / 想起来了」两档在界面上不再可达 ——
间隔增长会比以前慢一点，但复习不再是自己给自己打分。

**游戏里会告诉你**：打到新卡时战斗屏挂一句"新卡每击只有三成伤害——先把它背熟"，败局结算会给
"背熟后每击伤害更高"的下一步引导；所以不用先读下面这段也能自己摸出来。

**首战是"教学局"**（Plan 5 数值改进，D39）：第一场的敌人血量只有正常的三成，全 `new` 卡十击即可打穿
——新手期不再有"数学上不可能赢"的门槛（旧数值下 `new` 每击 1 点、`learning` 6 点，都低于 7 点/张的分摊线，
玩家"背过一遍回来还是输"）。打完这一场立刻回到正常难度，界面上会明确写着这是教学局。

**一处必败仍在**（刻意的苦修设计，D34）：**第一头卷灵首战打不过**——引导域 10 张卡 ⇒ Boss 池 150 点，
刚攒够 15 次复习时卡是 `review`（每击 12 点）⇒ 十击约 120 点；首败会把卡推到 `mastered`（每击 18 点），
**第二次挑战即可净化**。

### 练功（木桩）：不判胜负，也不推卷灵达标

菜单第五个入口「练功」里可以按领域**看旧卡**并**勾选要练的卡**（默认勾"到期 + 新卡"），
底部那条「开始练功」进入**木桩练功**：

- **领域可以多选合练**：打开一个领域就把"该练的"算进来，点卡列表顶部的「← 换领域」再打开别的领域
  ——勾选**跨领域累加**，**上限是几个领域加在一起 25 张**（领域小、卡不够一局时不再被卡住）。
  领域行会显示「本次已选 N 张」，已加入的行旁边有「移出本次」，「清空勾选」= 这次一张都不练；
  底部那条「本次已选 N / 25 张 · 来自 M 个领域」在**领域列表上也在**，所以不用先进某个领域就能开练。
  你自己勾的卡一定进池；你**取消**过的卡不会被自动补齐又勾回来；
- 敌人是**练功木人桩**：**耐久不降、也不反击**，所以**不会判胜负**（打完池子即"练功完成"）；
- 经验按遭遇战的 **1/20**（≈1 点/局）——刷一百遍差不多升一级，"算你努力了"；
- **不进战绩榜、不计局数**，也**不进"有效复习日"账本**：练功能推进 SRS（卡真的更熟了），
  但**推不动卷灵达标**——木桩不能当零风险刷 Boss 的捷径；
- 作答方式与正常战斗完全一致（选择题 / 问答模式 / 直接看答案），练功里同样每次都会展开完整答案。

### 采新卡：把外面的知识带进来

练功屏的第二个分区「采新卡」（需要你在「设置 → AI」里配好 Key）。**卡组页也开了同一个入口**
（列表下方的「采新卡（从链接 / 文章）」→「去练功 → 采新卡」）——建卡的事都归在一起，
从卡组页点进去**直接落在采新卡分区**，不用再自己切一次。四条路，都走同一条管线：
**拿到正文 → AI 改写成候选卡 → 你逐条勾选 → 存入某个领域**。

#### 来源库：不用自己找链接（D53）

采新卡最上面是**固定来源库**，内置一个标准领域「**AI / 机器学习前沿**」：

| 直连可读（点了真的出内容） | 覆盖什么 |
|---|---|
| HF Daily Papers | 每天的论文——**摘要随响应一起回来**，直接能生成卡 |
| vLLM / transformers 版本发布 | 推理工程与生态的版本要点（更新说明正文很全） |
| DeepSeek 仓库动态 | DSH（deepseek-harness）等全系仓库最近更新了什么 |
| HF 热门模型 | 开源模型、LoRA、微调、量化：大家在跑什么 |
| Hacker News 头条 | 开发者当天在讨论什么（标题+分数，正文去原文看） |
| GitHub Blog / Databricks / Lil'Log | 工程实践、数据工程、Agent/RAG 综述 |

用法：**选来源 → 看最新 → 「用这篇」**。响应里带了正文的（HF 论文、GitHub 更新说明）**就地生成**，
只带标题链接的走抓取管线。

另外还有一档标着「**需读取服务**」的源（OpenAI 官方新闻、Hugging Face Blog、Google DeepMind、
arXiv cs.AI/cs.LG、Towards Data Science、Latent Space、量子位）：**它们是可达的，但响应里没有 CORS 头，
浏览器无权读** —— 这是浏览器的安全模型，不是代码能绕的。

**配一个读取服务它们就真能用**（「设置 → AI → 读取服务」，实测 r.jina.ai 可达且开了 CORS）：

- 配了之后点「看最新」会**先经那台服务**去读（这些源直连必然读不到，先试直连等于白跑一趟）；
- 状态行会写明「**经读取服务取回**」，你能看出来这次的链接出过门；
- **代价如实说**：这一步等于**把这个源的地址发给那台第三方服务**（正文也经它回来）。不想发就别配，
  界面会给你"打开原文去复制"这条出路；
- 第一次读会**慢几秒**（arXiv 一天的源经它一转 ≈2.6MB / 3–4 秒，我们只取最前面 20 条）；
- 读不到时会**分两侧说清是谁没读到**（"读取服务 429 限流" vs "这个站没开跨域"要做的处置完全不同）。

**这一整份库你自己也能改**：加源（名称 + 链接 + 类型）、删源（含内置的）、一键「恢复推荐来源」。
你改的那部分只存在**这台设备**上（`localStorage`，不进存档、不进备份）。逐条实测数据与选源理由见
[`docs/SOURCES.md`](docs/SOURCES.md)。

| 你怎么给来源 | 实际会发生什么 |
|---|---|
| **粘一段正文**（最稳） | 直接生成候选（长文自动分块，一次掘完） |
| **给一个链接** | 能直读就直读（少数站点）；是一张目录页就**列出条目让你挑一条进去**（"进入一层"）；抓不到就如实说明并把链接**存进待读清单**，你读完把正文粘回来即可 |
| **系统分享进来** | 装到主屏后（Android Chrome），在微信/浏览器里点「分享 → 知识侠客」，链接或正文会直接进采新卡 |

- **候选默认一条都不勾**：这些内容是从你**还没读过**的页面上改写的，请过一眼再决定留哪几条
  （卡组页的 AI 辅建卡是"默认全勾"——那里的字是你自己粘的，风险不同）。
- **每日额度 200 张**（与卡组页 AI 辅建卡**共用一本账**），屏上随时显示"今日还剩多少"；
  单次最多 20 张；到顶会明确说"明天再来"，不会悄悄少给。
- 抓不到几乎是常态：**公众号 / 知乎 / 腾讯新闻 / 澎湃实测都没有 CORS 头**，浏览器无权读它们的正文。
  这是浏览器的安全模型，不是代码能绕的。所以产品把"抓不到"当成正常路径来设计：
  给一句实话 + **把下一步递到你手里** —— 状态行会告诉你怎么做、旁边出现「**打开原文去复制**」，
  光标也已经落在粘贴框里（复制 → 返回 → 粘贴，两次点击就完事），链接同时进了待读清单不会丢。
- **公众号的实测数据**（2026-09）：单篇原始 HTML 约 **3.6MB**（多为脚本与样式）、正文四千余字、
  响应里**没有任何 CORS 头**。抓取层因此把体积上限设为 4MB —— 这样"经读取服务拿原始 HTML"
  这条兜底路才走得通（解析实测 90ms，只保留 ≤12000 字正文）。
- 如果你愿意把链接交给一个第三方读取服务（自建网关 / r.jina.ai 之类），可以在「设置 → AI → 读取服务」
  里填它的地址与 Key：填了之后抓不到会自动经它转一手 —— **链接会外发给那台服务**，请自行判断是否接受。
- 待读清单只存在**本机浏览器**里（≤30 条），不进存档、不进备份，可一键清空。

**边界（如实说）**：我们**不做爬虫** —— 一次只处理你主动递进来的一份内容，不批量、不定时、不抓榜单、
不绕过任何反爬或跨域限制；正文只用于本次生成、不落盘存档（卡上只留来源链接）。

### 想从头再玩一遍（重置存档）

「设置 → 存档 → 重置存档」（两步确认：第一次点击只展开代价说明，第二次点「确认重置」才真清）。
它会清空卡库（**含你自己加的卡与领域**）、复习进度、等级与经验、战绩榜、序章记录，
**设置（阈值 / 池子 / 复习参数）也回到默认**，然后立刻重新装上 4 个预置领域 30 张卡——
不用刷新页面，也不用重装 App。**这一步不能撤销**，所以确认面板里并排放着「先导出备份」。

**AI 的 Key 不会被重置**：它存在浏览器 `localStorage` 里，**不在存档内**（这正是它不进备份的原因），
所以重置后不用重填；想清它请用同一个分组上面的「清除 Key」。

## AI 辅建（可选，用你自己的 Key）

游戏本身**完全离线**；AI 只是可选加速器，不用它也一切照常。要用就在「设置 → AI」里填三样：
接口地址（内置 DeepSeek / 通义千问预设，也可自定义任何 OpenAI 兼容网关）、模型名、API Key。

三个用途：

| 用途 | 在哪 | 产出怎么进游戏 |
|---|---|---|
| **辅建卡** | 卡组页「AI 辅建卡」 | 粘一段笔记 → 生成候选卡 → 逐条勾选/编辑 → 点「加入卡库」才落盘（来源标 `llm`） |
| **称号建议** | 备战页的卷灵称号弹窗「让 AI 起几个名」 | 点候选只是**填进输入框**，仍要玩家点确认 |
| **图鉴彩蛋** | 藏书阁自建领域「让 AI 写彩蛋」 | 先预览，点「用这段」才写入 |
| **问答判卷** | 战斗屏的问答模式（设置里切换） | 你的理解是否与这张卡的答案一致 + 缺了哪些要点；判不了就交回你自己定 |

### 自己验证一次真实调用（我没有你的 Key，所以这一步只能你做）

1. 手机上打开线上地址 → 设置 → AI：选「DeepSeek」预设，粘上你的 Key，点「保存」，再点「测试连接」——
   应看到「连接正常。」；若看到 401/403 就去核对 Key，429 说明被限流（等一会儿）。
   拿不准模型名就点「**拉取模型列表**」——它直接问你自己的账号有哪些模型，点一下即填入
   （DeepSeek 现在是 `deepseek-flash` / `deepseek-v4-pro`；旧名 `deepseek-chat` 已停用，填它会得到 400，
   而 400 的提示里会带上服务商的原话，方便自查）。
2. 卡组 → 「AI 辅建卡」：随便粘一段笔记（三五句话）→「生成候选」→ 应该出现几条候选卡；
   勾掉不想要的、改改措辞 →「加入卡库」→ 回到卡组列表能看到它们（来源标 `llm`，会计入精神属性）。
3. 每张卡都**没有自动落库**：不点「加入卡库」就什么都不会发生——你可以放心试。

### 关于 Key 与数据（请务必知道）

- **Key 只存在这台设备的浏览器里**（`localStorage`），**不进存档、不进备份文件**——备份会被分享/拷贝，
  Key 进去就是泄漏。代价是：**换设备或清浏览器数据要重新填一次**。
- **重置存档不会清掉 Key**（它不在存档里）——这是刻意的：重置是"重新开始玩"，不是"清空这台设备"。
- 存储是**明文**的（浏览器里没有可信的密钥保管处，"前端加密"只能把钥匙放同一处，属于自欺）。
  设置页提供「清除 Key」。
- **数据最小化**：只发送你**当场粘贴的那段文字**，或领域名 + 最多 5 条卡片正面。
  不发送 SRS/复习记录/战绩榜/存档元信息，**绝不整档上传**。
- **一处例外（问答模式，必须让你知道）**：用问答模式时，会把**这张卡的答案 + 你的输入**
  发给你的服务商 —— 不把答案发出去就没法判断"你的理解是否与它一致"。范围锁死在
  **问答模式 + 你点提交那一刻 + 单张卡**；其余三条路径（辅建卡 / 称号 / 彩蛋）一字不改。
- **产出视为不可信**：模型返回的文本会先过严格解析（JSON 结构、字段类型、长度与条数上限、
  控制字符剥离），**任何写入都要你逐条确认**；渲染一律走文本节点，不存在 HTML 注入面。
- **没有后端**：请求从你的浏览器直接发给服务商（所以你的 Key 不经过任何中间服务器）。
  实测允许浏览器直连（CORS 预检通过）：**DeepSeek** 与**通义**（DashScope 兼容模式），故列为预设。
  **OpenAI 官方域名本机不可达**（这台设备的网络把 `api.openai.com` 解析成了无关地址，属网络干扰，
  并非对它跨域策略的结论）——因此没有验证、也就没有列预设。若你的网络能直连它或任何兼容网关，
  在「自定义」里填 `https://api.openai.com/v1` 之类的地址即可。

## 质量门禁：`npm run verify`

[![CI](https://github.com/luyangk/pixel-flashcard-rpg/actions/workflows/ci.yml/badge.svg)](https://github.com/luyangk/pixel-flashcard-rpg/actions/workflows/ci.yml)

一条命令跑完五段门禁，**全绿才允许 commit**（CI 与部署流水线跑的都是这一条）：

```bash
npm run verify        # = typecheck && check:purity && test && build:only && smoke:dist
```

| 段 | 命令 | 把什么变成机器检查 |
|---|---|---|
| 类型 | `npm run typecheck` | TypeScript strict（含 `@ts-expect-error` 的"类型层确实拦住了"断言） |
| 纯净 | `npm run check:purity` | `src/core/**` 禁 DOM/Node API、禁 `Date.now(`、禁 `Math.random(`（`scripts/check-core-purity.mjs`） |
| 测试 | `npm test` | Vitest 全量（当前 **87 文件 / 1270 用例**；另有 11 条**真产物**冒烟只在这一段之后的 `smoke:dist` 里跑），含 headless 逻辑链冒烟与**有画面的可玩性冒烟** |
| 构建 | `npm run build:only` | 真实打包（Vite build）——**dev server / 打包期的模块解析故障只有它能挡**（vitest 自带别名，曾让一条 `@core/*` 解析失败在 789 条全绿的情况下溜到真浏览器里） |
| 产物 | `npm run smoke:dist` | 把 `dist/` 里的**真 bundle 当模块跑起来**（happy-dom 造浏览器环境）：启动到序章第一屏、旁白逐字、连点 8 屏进菜单。源码全绿 ≠ 产物能跑，这一步补的就是那道缝 |

发布走 `.github/workflows/deploy.yml`：main 推送 ⇒ 同一套 verify ⇒ `dist/` 上传为 Pages artifact ⇒ 发布。
**部署不会再跑一遍额外的检查**（verify 就是唯一的门禁），所以本地绿 ≠ 一定能发，但本地红一定发不出去。

单跑某一部分：`npm test -- tests/e2e/playable.smoke.test.ts`、`npm run build`（typecheck + Vite 构建）。
