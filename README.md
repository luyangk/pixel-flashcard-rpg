# 知识侠客（Pixel Flashcard RPG）

把间隔重复（SM-2）复习包装成回合制卡牌战斗的**本地优先单机游戏**：答对一张卡就造成一次伤害，
打穿一个知识领域的"卷灵"Boss，把学过的知识变成角色的等级与六维。纯前端、无后端、无账号——
因此进度的唯一保全手段是**导出 JSON 备份**，离线也能玩。

## 现在就能玩

**手机浏览器直接打开：<https://luyangk.github.io/pixel-flashcard-rpg/>**
（GitHub Pages，main 分支推送后自动发布。）

想当 App 用：在浏览器菜单里选「添加到主屏幕」——之后从图标启动是全屏无地址栏的，
而且**第二次打开不需要联网**（Service Worker 会把页面、脚本、样式与全部素材缓存下来；
存档一直在本机 IndexedDB，从不上传）。首次打开建议连着 Wi-Fi 等它加载完再看一眼。

技术底座是四层分离：`src/core/` 纯 TypeScript 逻辑核（零 DOM、零平台 API、时间与随机全部入参化）、
`src/platform/` 平台能力抽象（IndexedDB / 内存存储、时钟、时区、随机播种、图片与文件口）、
`src/app/` 编排层（会话控制器、Boss 净化、预置内容种子、导入导出）、`src/ui/` + `src/stage/`
（原生 DOM 屏组件与 Canvas 战斗舞台，无框架、无游戏引擎）。

## 玩一局（本地调试）

> 手机上最省事的是直接用上面的线上地址；下面这套是**改代码时**用的。
> 注意 dev server **不会**注册 Service Worker（`import.meta.env.PROD` 才注册），
> 所以本机改一行立刻见效，不会被离线缓存挡住。

```bash
npm install                       # 首次；/sdcard（noexec）上还需 node scripts/link-native-bindings.mjs
npm run dev -- --host 127.0.0.1   # 只在本机浏览器打开 http://127.0.0.1:5173
# 想在**手机**上玩：绑到局域网，然后用手机浏览器访问 http://<电脑局域网IP>:5173
npm run dev -- --host 0.0.0.0
```

首次启动会自动灌入 4 个预置领域（成语典故 / 英语词根 / 生活常识 / 唐诗，共 30 张手写卡）。
**玩法要点**：伤害跟着"背熟程度"走——`new` 每击 `atk × 0.3`（三成）、`learning` ×0.7、
`review` ×1.0、`mastered` ×1.5。所以循环是：背卡 → 稳定度晋升 → 每击伤害翻倍 → 打赢遭遇战攒经验升级
→ 回头挑战卷灵 Boss。战败不是白输：败局会演出"假记忆注入"（LORE §5.5，纯演出、零数值后果）。

**游戏里会告诉你**：打到新卡时战斗屏挂一句"新卡每击只有三成伤害——先把它背熟"，败局结算会给
"背熟后每击伤害更高"的下一步引导；所以不用先读下面这段也能自己摸出来。

**首战是"教学局"**（Plan 5 数值改进，D39）：第一场的敌人血量只有正常的三成，全 `new` 卡十击即可打穿
——新手期不再有"数学上不可能赢"的门槛（旧数值下 `new` 每击 1 点、`learning` 6 点，都低于 7 点/张的分摊线，
玩家"背过一遍回来还是输"）。打完这一场立刻回到正常难度，界面上会明确写着这是教学局。

**一处必败仍在**（刻意的苦修设计，D34）：**第一头卷灵首战打不过**——引导域 10 张卡 ⇒ Boss 池 150 点，
刚攒够 15 次复习时卡是 `review`（每击 12 点）⇒ 十击约 120 点；首败会把卡推到 `mastered`（每击 18 点），
**第二次挑战即可净化**。

### 想从头再玩一遍（重置存档）

「设置 → 存档 → 重置存档」（两步确认：第一次点击只展开代价说明，第二次点「确认重置」才真清）。
它会清空卡库（**含你自己加的卡与领域**）、复习进度、等级与经验、战绩榜、序章记录，
**设置（阈值 / 池子 / 复习参数）也回到默认**，然后立刻重新装上 4 个预置领域 30 张卡——
不用刷新页面，也不用重装 App。**这一步不能撤销**，所以确认面板里并排放着「先导出备份」。

**AI 的 Key 不会被重置**：它存在浏览器 `localStorage` 里，**不在存档内**（这正是它不进备份的原因），
所以重置后不用重填；想清它请用同一个分组上面的「清除 Key」。

## AI 辅建（可选，用你自己的 Key）

游戏本身**完全离线**；AI 只是可选加速器，不用它也一切照常。要用就在「设置 → AI」里填三样：
接口地址（内置 DeepSeek / 通义千问预设，也可自定义任何 OpenAI 兼容网关）、模型名、API Key。

三个用途：

| 用途 | 在哪 | 产出怎么进游戏 |
|---|---|---|
| **辅建卡** | 卡组页「AI 辅建卡」 | 粘一段笔记 → 生成候选卡 → 逐条勾选/编辑 → 点「加入卡库」才落盘（来源标 `llm`） |
| **称号建议** | 备战页的卷灵称号弹窗「让 AI 起几个名」 | 点候选只是**填进输入框**，仍要玩家点确认 |
| **图鉴彩蛋** | 藏书阁自建领域「让 AI 写彩蛋」 | 先预览，点「用这段」才写入 |

### 自己验证一次真实调用（我没有你的 Key，所以这一步只能你做）

1. 手机上打开线上地址 → 设置 → AI：选「DeepSeek」预设，粘上你的 Key，点「保存」，再点「测试连接」——
   应看到「连接正常。」；若看到 401/403 就去核对 Key，429 说明被限流（等一会儿）。
   拿不准模型名就点「**拉取模型列表**」——它直接问你自己的账号有哪些模型，点一下即填入
   （DeepSeek 现在是 `deepseek-flash` / `deepseek-v4-pro`；旧名 `deepseek-chat` 已停用，填它会得到 400，
   而 400 的提示里会带上服务商的原话，方便自查）。
2. 卡组 → 「AI 辅建卡」：随便粘一段笔记（三五句话）→「生成候选」→ 应该出现几条候选卡；
   勾掉不想要的、改改措辞 →「加入卡库」→ 回到卡组列表能看到它们（来源标 `llm`，会计入精神属性）。
3. 每张卡都**没有自动落库**：不点「加入卡库」就什么都不会发生——你可以放心试。

### 关于 Key 与数据（请务必知道）

- **Key 只存在这台设备的浏览器里**（`localStorage`），**不进存档、不进备份文件**——备份会被分享/拷贝，
  Key 进去就是泄漏。代价是：**换设备或清浏览器数据要重新填一次**。
- **重置存档不会清掉 Key**（它不在存档里）——这是刻意的：重置是"重新开始玩"，不是"清空这台设备"。
- 存储是**明文**的（浏览器里没有可信的密钥保管处，"前端加密"只能把钥匙放同一处，属于自欺）。
  设置页提供「清除 Key」。
- **数据最小化**：只发送你**当场粘贴的那段文字**，或领域名 + 最多 5 条卡片正面。
  不发送答案、不发送 SRS/复习记录/战绩榜/存档元信息，**绝不整档上传**。
- **产出视为不可信**：模型返回的文本会先过严格解析（JSON 结构、字段类型、长度与条数上限、
  控制字符剥离），**任何写入都要你逐条确认**；渲染一律走文本节点，不存在 HTML 注入面。
- **没有后端**：请求从你的浏览器直接发给服务商（所以你的 Key 不经过任何中间服务器）。
  实测允许浏览器直连（CORS 预检通过）：**DeepSeek** 与**通义**（DashScope 兼容模式），故列为预设。
  **OpenAI 官方域名本机不可达**（这台设备的网络把 `api.openai.com` 解析成了无关地址，属网络干扰，
  并非对它跨域策略的结论）——因此没有验证、也就没有列预设。若你的网络能直连它或任何兼容网关，
  在「自定义」里填 `https://api.openai.com/v1` 之类的地址即可。

## 质量门禁：`npm run verify`

[![CI](https://github.com/luyangk/pixel-flashcard-rpg/actions/workflows/ci.yml/badge.svg)](https://github.com/luyangk/pixel-flashcard-rpg/actions/workflows/ci.yml)

一条命令跑完五段门禁，**全绿才允许 commit**（CI 与部署流水线跑的都是这一条）：

```bash
npm run verify        # = typecheck && check:purity && test && build:only && smoke:dist
```

| 段 | 命令 | 把什么变成机器检查 |
|---|---|---|
| 类型 | `npm run typecheck` | TypeScript strict（含 `@ts-expect-error` 的"类型层确实拦住了"断言） |
| 纯净 | `npm run check:purity` | `src/core/**` 禁 DOM/Node API、禁 `Date.now(`、禁 `Math.random(`（`scripts/check-core-purity.mjs`） |
| 测试 | `npm test` | Vitest 全量（当前 **67 文件 / 979 用例**；另有 5 条**真产物**冒烟只在这一段之后的 `smoke:dist` 里跑），含 headless 逻辑链冒烟与**有画面的可玩性冒烟** |
| 构建 | `npm run build:only` | 真实打包（Vite build）——**dev server / 打包期的模块解析故障只有它能挡**（vitest 自带别名，曾让一条 `@core/*` 解析失败在 789 条全绿的情况下溜到真浏览器里） |
| 产物 | `npm run smoke:dist` | 把 `dist/` 里的**真 bundle 当模块跑起来**（happy-dom 造浏览器环境）：启动到序章第一屏、旁白逐字、连点 8 屏进菜单。源码全绿 ≠ 产物能跑，这一步补的就是那道缝 |

发布走 `.github/workflows/deploy.yml`：main 推送 ⇒ 同一套 verify ⇒ `dist/` 上传为 Pages artifact ⇒ 发布。
**部署不会再跑一遍额外的检查**（verify 就是唯一的门禁），所以本地绿 ≠ 一定能发，但本地红一定发不出去。

单跑某一部分：`npm test -- tests/e2e/playable.smoke.test.ts`、`npm run build`（typecheck + Vite 构建）。
