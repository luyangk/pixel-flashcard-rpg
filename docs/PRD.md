## 1. 产品定位

| 维度 | 结论 |
|---|---|
| 产品名称 | **知识侠客**（只用中文名；仓库代号沿用 `pixel-flashcard-rpg`） |
| 一句话定义 | 把「背闪卡」变成「打怪」的像素风卡牌对战 RPG：记忆卡片即战斗装备，只有记进大脑的知识才能伤害混沌 |
| 首版受众 | **自用为主**，设计可按个人口味激进，不迎合大众审美 |
| 目标形态 | **手机浏览器网页（PWA，完整离线化）**，架构保留日后打包 APK / 移植小程序的可能 |
| 单局时长 | 2–3 分钟（含备战与结算），贴合碎片时间 |
| 核心体验承诺 | 玩家感到的强度增长必须直接来自真实记忆水平的提升，二者不可解耦 |
| 叙事承诺 | 故事不是包装纸：世界观法则与战斗机制严格同构（见 LORE §2），叙事全套进 MVP |

### 平台约束（由"保留打包可能"倒推）
- 核心逻辑（SRS、数值、卡组数据）与渲染层严格分离，纯 TypeScript 模块，不引用任何 DOM / 平台 API。
- 存档走抽象存储接口，便于替换为 `SharedPreferences`（APK）或 `wx.setStorage`（小程序）。
- 不依赖只在特定容器可用的能力（如微信登录、推送）作为玩法前置条件。

## 2. 核心玩法：卡牌对战 RPG

### 2.1 属性体系（本作的辨识点）

学习数据直接映射为角色战力：

| 属性 | 数据来源 | 影响 |
|---|---|---|
| **体力** | 已完成记忆的卡片数量 | 防御力主因子 |
| **精神** | 自建卡片的数量 | 攻击力主因子 |
| **等级** | 关卡累计经验值 | 提升所有基础属性 |
| **熟练度** | 单张卡的 SRS 复习历史 | 该卡释放时的伤害倍率 |

> ⚠️ 已知设计风险：「精神 = 自建卡数量」会让玩家倾向**灌水建卡**而非认真学习。
> 缓解方案见 §6.4 —— 只有**通过至少一轮完整复习并进入长期记忆**的自建卡才计入精神属性。
> 此条为首版必须验证的平衡假设（§8 待验证项 A1）。

### 2.2 出卡节奏：系统依序出卡

- 战斗开始后，卡池顺序由 **SRS 优先级队列**决定，玩家不参与选牌。
- 玩家唯一操作：**作答**（看正面 → 回想背面 → 自评掌握程度）。
- 答对 → 该卡作为武器释放攻击，伤害 = 基础攻击 × 熟练度倍率 × 随机浮动。
- 设计意图：把「复习时机是否科学」交给算法，把「操作负担」降到最低，符合低压休闲定位。

### 2.3 奖惩机制：答错仅空转

- 答错：**本回合无输出**，敌人不额外造成伤害，不扣血、不断连击惩罚。
- 战斗失败的唯一路径是**卡池耗尽仍未击杀敌人**（超时判定），而非答错累积。
- 理由：面向记忆场景，压力会直接抑制学习意愿；失败感来自"这关还需要更熟练"，不是"我错了要挨打"。

### 2.4 战斗结构：无尽流遭遇战 + 领域卷灵 Boss

- **普通遭遇战**：一场 = 一波卡池（**10–15 张为常规体验**；备战屏另给 25 张的"长局"挡位，见 D37），打完结算经验。无固定章节，无尽流（§11 D14）。
- **玩家预选主领域**：开战前可选本场主领域（不选则随机）；选定后该场卡池以该领域为主、跨主题混合为辅。
- **领域卷灵 Boss**（叙事绑定见 LORE §4.2/§5）：
  - **触发**：某卡组（= 一个知识领域）的**累计有效复习次数**达标。有效复习 = 间隔 ≥1 天的复习（同日重复只计首次），防短期突击灌水。
  - **阈值**：默认 30 次；设置页提供 15/30/50 三档难度开关；首个引导领域（生活常识）特调 15 次，保证新用户 3 天内见到第一头 Boss。
  - **构成**：Boss 战卡池全部来自该领域主题；击败 = 净化 → 图鉴条目 + 一次性大额经验。
  - **重玩**：已净化领域可主动「重战」当主题练习关（点藏书阁条目直达），不再给剧情只给经验。
  - **自建领域**：用户自建卡组自动获得 Boss 资格；默认称号模板「{卡组名}·卷灵」，首次触发时弹窗询问：接受默认 / 自拟（≤30 字）/ 采纳 LLM 建议名（候选须人工确认）。
- 明确**不做**：多波连战、Roguelike 爬塔选路、Boss 干扰技能（高熟练卡临时失效——评估过，平衡风险大，推迟）。

## 3. 备战环节

```
选择关卡 → 预选主领域（可跳过=随机）→ 主题筛选（可多选 / 纯随机）→ 生成卡池 → 开战
```

- 卡池构成：**80% 系统智能配卡 + 20% 玩家自选**。
  - 80% 部分由 SRS 到期队列按紧迫度自动填充（保证科学性）。
  - 20% 部分留给玩家加练自己想强化的内容（保证自主感）。
- 支持**主题（Tag）多选筛选**，也可整体选「纯随机」。
- 卡池不足时降级策略：放宽主题限制 → 引入未到期卡 → 提示玩家补充卡组。

### 3.1 作答模式（v2.6 新增，D41/D42）

自评（"我觉得我记住了"）没有验证、全靠自觉，是本作在学习有效性上最大的一处妥协。
v2.6 起**默认出选择题**，并提供问答模式与"直接看答案"两条退路。三者的共同铁律：
**作答之后必须先在屏上展开完整答案，再由玩家点「继续」放行** —— 那是学习发生的地方。

| 模式 | 交互 | 评分 |
|---|---|---|
| **选择题（默认）** | 正面 + 选项（默认 4 个：1 正确 = 该卡背面 + 3 干扰）。选中即判分 | 答对 → `good`；答错 → `again` |
| **直接看答案** | 任何时候可点；跳过作答 | `again` —— 看答案记为答错（没回忆就记正分，等于把自评时代的漏洞换个地方留着） |
| **问答模式（可切换）** | 正面 + 输入框，玩家用自己的话写理解 → 自带 LLM 判定 | 判对 → `good`；判错 → `again`；**判定失败绝不猜**，交回玩家二选一自评 |

**选项从哪儿来（三级，零临时调用）**：
1. **卡上自带的 `choices`** —— 由模型在**生成这张卡的那一刻**一并产出（辅建卡 / 采新卡两条路都产出），
   随卡存进存档。复习时**不再临时调模型**（省额度、也省等待）；
2. 不够 3 个时，用**同领域其他卡的背面 + 它们自带的 `choices`** 补齐（本地、即时、零消耗，
   且选项组合会随卡库变化，不至于每次都是同一组）；
3. 还不够就**少给选项**（2–3 个）；连一个干扰项都凑不出（领域只有这一张卡）⇒ 回落看答案并在屏上说明原因。

**屏幕与判分细节**：
- 选项在屏上**截断预览**（约 40 字 + 省略号）；**完整答案照旧在判定面板里全文展示**。
  截断按码点；**截断后与其他选项撞车的干扰项直接不要**（宁可少一个选项，也不显示两个
  "看起来一模一样"的选项 —— 加长到能区分会把预览拉到 60+ 字，正好抵消截断的初衷）。
  若连一个能区分的干扰项都凑不出 ⇒ 回落"看答案"。
- **「其实是猜的」**：答对之后判定面板里有一个不显眼的小按钮，点了把这次改判为 `again`。
  默认不用点（满足"答对了就是记住了"的流畅感），只有靠蒙的时候才多点一下 —— 4 选 1 的 25% 蒙对率
  不该被静默记成"记住了"（D41）。
- **评分二档化**：UI 只发 `good` / `again`（`GRADES` 与 core 引擎**不动**，四档语义完整保留）。
  代价如实登记：`easy` 的 `interval×1.3` 与 `EF+0.1`、`hard` 的轻微下调**不再可达**，
  间隔增长变慢、复习负荷略升。
- **模式切换**：设置页有默认模式；战斗屏可**本局内切换**，切换即写回设置、下一局沿用。
- **问答判定的反馈**（D42）：模型回三样 —— 对/错、一句话理由、**缺了哪些要点**（≤5 条、每条 ≤60 字）。
  「你答对大意但漏了作者」才算真的复习到了。
- **判定的闸**：**300 次/天**上限（与"新知识 200 张/天"是两本账）。到顶**不锁复习**：
  自动回落成"你自己定对错"的二选一，并在屏上说明原因。
- **无 Key / 无网络 / 判定失败 / 领域只有一张卡**都在屏上说明原因，并给出当时**真正可用**的下一步，
  绝不静默降级。

## 4. 内容体系（五轨）

| # | 轨道 | 说明 | 版本 |
|---|---|---|---|
| 1 | **预置主题卡组** | 首发 4 领域：成语典故 / 英语词根 / 生活常识 / 唐诗（每域一个卡组 + 一头卷灵 Boss + 手写彩蛋文案） | MVP |
| 2 | **热点新知识** | **玩家驱动摄入**（v2.6，D43）：玩家给的链接 / 分享进来的文章 / 粘来的正文 → LLM 改写为闪卡 → 逐条选择入库。不做站点爬虫、不做热搜榜单 | Plan 7 |
| 3 | **指定领域构建** | 同 2 的管线，但输入为用户指定的领域关键词 | 二期 |
| 4 | **纯个人创建** | 手动录入 + CSV/JSON 导入；**LLM 辅建（粘贴文本→抽取候选卡→人工审核）** | MVP（含 LLM 辅建） |
| 5 | **叙事内容** | 序章脚本、战报模板池（约 30 条）、暗线三幕、Boss 称号、图鉴彩蛋 | MVP |

### 4.1 轨道 2/3 的发现流交互（Swipe Deck）

- **上滑**：继续阅读下一张知识卡详情
- **左滑**：加入我的知识库（成为可装备的战斗卡）
- **右滑**：舍弃，不再出现
- 交互模型刻意对齐短视频 App，降低认知成本。

### 4.2 知识摄入管线（v2.6 重写：玩家驱动，D43）

```
玩家提供来源（链接 / 系统分享进来的文章 / 粘贴的正文）
        ↓
   尽力直读网页（浏览器直连）→ 抽正文 + 抽页面上的条目链接
        ↓           ↳ 直读被拒（CORS）时：说清原因，转"粘贴正文 / 分享进来"
   进入一层：列出该页面上的条目，玩家选一条 → 再抽它的正文
        ↓
   LLM 改写为「正面-背面」闪卡（分块、去重、条数上限）
        ↓
   候选卡列表 → 玩家逐条勾选/编辑 → 选择存入哪个领域 → 落库（来源链接随卡保存）
```

**为什么是"玩家驱动"而不是"爬虫"**（这是对 §11 D09 的**有意收窄**，不是推翻）：
- D09 拒绝的是"批量抓中文热搜/新闻站"（版权与反爬风险）。本管线**不提供**任何批量/定时/榜单能力，
  也不做任何绕过：一次处理玩家主动递进来的**一份**内容，卡上保留来源链接以便溯源。
- 版权边界写死在产品里：生成的卡是**改写后的问答**（不把原文整段塞进卡面），
  正文只用于本次生成、不落盘存档。

**浏览器直连的现实约束（实测，不是推测）**：普通网页的响应里没有 `Access-Control-Allow-Origin`，
页面脚本无权读取它们的正文。实测（本机 curl 取响应头）：`mp.weixin.qq.com`、`www.zhihu.com`、
`news.qq.com`、`www.thepaper.cn` **均无 CORS 头**。因此：

| 来源 | 直接直读 | 现实可用路径 |
|---|---|---|
| 公众号文章 / 知乎 / 新闻站 | ❌ | 「分享」把链接递进来 + 粘贴正文（手机上的常规操作）；或玩家自己配置读取服务（下方可选） |
| 开放接口 / RSS / 维基 API / GitHub raw 等少数放行站点 | ✅ | 链接 → 条目列表 → 进入一条 → 生成，全自动 |
| 玩家自己的站点或公司内网（同源/已放行） | ✅ | 同上 |

- **待读清单**：直读被拒时把链接存进本机清单（≤30 条，可一键清空），玩家读完回来粘正文即出箱（D47）。
- **来源库（D53）**：内置一个**标准领域**（AI / 机器学习前沿）的来源清单，玩家"选来源 → 看最新 → 用这篇"
  即可进生成管线。来源分两档并**在行上标出来**：**直连可读**（实测有 ACAO）与**需读取服务**
  （可达但无 ACAO，界面如实说、并给"配读取服务 / 打开原文去复制"两条出路）。玩家可以自己加源、
  删源（含内置的）、一键恢复推荐；这份库只存本机 `localStorage`（不进存档、不进备份）。
  **逐条实测数据与筛选记录见 `docs/SOURCES.md`。**
- **可选"读取服务"**（设置 → AI，默认**关闭**）：玩家自己填一个读取服务（如 `r.jina.ai` 或自建网关）
  与 Key，由它把链接转成正文。**默认关闭**，打开时屏上如实写明"链接会经这台服务转一手"——
  隐私的账由玩家自己算，我们不替他决定。
- LLM 职责限定为**改写与结构化**，不承担事实创造；生成的每张卡保留来源链接以便溯源。

### 4.5 练功模块（v2.6 新增，D46/D47）

菜单里的「练功」是"知识准备"的总入口（入口文案见 D44），屏内三件事：

- **看旧卡**：选领域 → 浏览该领域全部卡（正面 / 背面 / 稳定度 / 来源 / 下次到期）+ 搜索；
  **能就地改内容**（正/背都能改，走新的 `updateCard` 写口）—— 顺手补上"卡只能删、不能改"这个既有缺口。
  卡列表顶部有**显式**的「← 换领域」按钮（D50：以前只有屏顶那个语义含混的「返回」，
  玩家进了领域就找不到回领域列表的路）。
- **多领域合练（D50）**：本次练功可以**同时纳入多个领域**，勾选跨领域**累计**（上限仍是合计 25 张）——
  领域小、卡不够一局时（"部分领域卡数不够"）不再被卡住。领域列表每行显示「本次已选 N 张」，
  已纳入的行带「移出本次」；底部常驻一条「本次已选 N / 25 张 · 来自 M 个领域」+「开始练功」，
  在**领域列表上也能直接开练**（不必先进某个领域）。打开一个领域 = 把它"该练的"卡纳入本次（可逐张改），
  再进别的领域继续累加；「清空勾选」= 本次一张都不练。
- **练这一域（木桩练功）**：卡列表上**勾选要练的卡**，默认勾「到期 + 新卡」，池上限 25（**跨领域合计**）。
  进入的是**新的战斗形态**（D46）：敌人是**练功木桩**（锁血：耐久条不降）、**不会反击**、
  **不判胜负** —— 打完池子即结算"练功完成：N 张"。经验按遭遇战的 **1/20**（≈1 点/局，
  刷一百遍也差不多一级，"算你努力了"），**不进榜单、不计 plays**，
  且**不进"有效复习日"账本**（练功推不动卷灵达标）——但**卡的 SRS 照常更新**（练了就是练了）。
- **采新卡**：§4.2 的摄入管线 → 候选审阅（**默认全不勾 + 一个「全选」**：抓来的页面你没读过，
  不替你预勾）→ 选目标领域（已有或新建）→ 入库。顶部常驻「今日新知识额度：剩 N / 200 张」（§6.6）。
- **待读清单**：抓不到的链接自动进箱（本机 `localStorage`，≤30 条，可一键清空），
  读完一篇文章回来粘正文、入库后自动出箱。这是"给一个站点链接、要能进一层"在 CORS 现实下
  唯一诚实的落地方式（清单里的正文只存本机、不进备份、不落盘存档）。

## 5. 成长与经济

- **等级**：关卡奖励经验值 → 升级 → 提升基础属性（攻防血量）。等级保持中性命名，**不做境界换皮**（LORE §8）。
- **叙事进度线**：净化领域数（3/6/9）驱动暗线三幕；藏书阁图鉴 = 收集 + 复习入口（点条目直开该领域练习关）。
- **商店**：关卡掉落金币，可购买卡槽扩容、装备栏位、外观等（**不做**随机装备词条掉落，§11 D07）。二期。
- **排行榜**：首版仅**本地榜**（设备内多玩家/多次记录排名）。联网好友榜留待后续，届时采用轻量 BaaS（Supabase / LeanCloud）只存分数与昵称，不自建服务器。

## 6. 数据与持久化

### 6.1 存储策略
- 首版**纯本地**：IndexedDB（卡组、复习历史、图鉴净化进度、存档）+ localStorage（设置）。
- **导出/导入存档 JSON**（含卡组 + SRS + 图鉴 + 设置）手动触发；每 7 天若未备份则首页弹一次"建议备份"横幅，不强制下载。
- 隐私：无任何服务端上报，无账号体系；LLM 调用为玩家 Key 直连，不经自建后端。
- **重置存档**（v2.5，D40）：设置页提供"清空并回到新装状态"的出口（`clear` → `reload` → 重灌预置内容
  → `flush`）。它的代价必须逐项写在屏上（含"设置也回默认"），且**不清 AI Key**（Key 在 localStorage，
  不属存档）。不可撤销 ⇒ 两步确认 + 一键导出备份。

### 6.2 卡片数据模型（草案）

```ts
interface Card {
  id: string;
  deckId: string;          // 所属卡组 = 知识领域 = 一头卷灵 Boss
  front: string;           // 正面（问题/提示）
  back: string;            // 背面（答案）
  source?: {               // 来源溯源（LLM 生成卡必填）
    type: 'preset' | 'hotspot' | 'domain' | 'manual' | 'llm';
    url?: string;
    createdAt: number;
  };
  srs: SRSState;           // 间隔重复状态
  tags: string[];          // 主题筛选依据
  choices?: string[];      // v2.6（D41）：模型在生成这张卡时一并产出的干扰项（≤5 条）
}

interface SRSState {
  ease: number;            // SM-2 难度因子
  interval: number;        // 当前间隔（天）
  reps: number;            // 连续正确次数
  lapses: number;          // 遗忘次数
  due: number;             // 下次到期时间戳
  stability: 'new' | 'learning' | 'review' | 'mastered';
  effectiveReviewDays: string[]; // 有效复习日期集（同日只计一次，Boss 计数口径）
}

interface Deck {            // v2：卡组即领域
  id: string;
  name: string;
  isPreset: boolean;
  bossName?: string;       // 卷灵称号；预置手写，自建默认模板+首次触发询问
  purifiedAt?: number;     // 净化时间戳（undefined = 未净化）
}
```

**v2.6 新增的两个可选设置位**（权威形状在 `src/core/types.ts`，三段式：types 可选 +
validateSave 在场严检 + migrateSave 为缺席档补默认）：

| 字段 | 形状 | 缺席默认 | 用途 |
|---|---|---|---|
| `answerMode` | `'choice' \| 'qa'` | `'choice'` | 作答模式（D41）；战斗屏可本局内切换并写回 |
| `Card.choices` | `string[]`（≤5 条、每条 ≤200 码点） | 不补（缺席 = 没有） | 生成卡时由模型产出的干扰项（D41 的第三级来源之上）；三段式：可选 + 在场严检 + 不补默认（与 `deck.egg` 同款） |
| `llmQuota` | `{ day: string; cards: number; judges: number }` | `{ day:'', cards:0, judges:0 }` | LLM 每日额度计数（D45）：`day` 为本地日界、**允许空串**（`''` = 「还没记过任何一天」，读侧按「新的一天」归零），跨天读时归零；`cards` 计生成张数（上限 200）、`judges` 计判定次数（上限 300） |

两条都**可选且缺席不拒**：新增字段做成拒绝点会让 v2.5 前的存档整包打不开（与 leaderboard 同款理由）。

### 6.3 复习算法
- 采用 **SM-2** 变体（成熟、无需训练数据、可解释），参数暴露于设置页可调。
- **ΔEF 门控（v2.1，Plan 2 spec 决策，§11 D27）**：采纳 Wozniak 原始语义——`easy(q=5)` 上调 EF、`good(q=3)` 不奖不罚保持 EF、`again/hard(q<3)` 下调 EF；修正 v1 照抄公式导致 good-only 长期 EF 单调下滑至地板的缺陷，保证"复习越熟间隔增长稳定"与伤害直觉一致。
- SRS 输出三重用途：① 决定备战卡池的到期优先级；② `stability`/`ease` 映射为战斗中的伤害倍率；③ **领域累计有效复习次数驱动 Boss 现身**（v2）。

### 6.4 「精神」属性的防灌水规则
- 自建卡仅在达到 `stability === 'review'`（完成首轮全部复习且未被判遗忘）后计入精神属性。
- 被判定 `lapses` 超阈值的卡从精神计数中移除，形成"维护强度"而非"堆积数量"的激励。
- Boss 计数的防灌水口径独立于此：**间隔 ≥1 天才计一次有效复习**（同日重复只算首次）。

### 6.5 战斗数值基线（v2.1 新增）
- **敌人 HP 由卡池反推**：`HP = 卡池张数 × 基准单卡伤害 × 难度系数`，难度系数：遭遇战 **0.7** / 卷灵 Boss **1.5**。性质：理论全对必胜且余量约 30%；错约 20%–40%（视熟练度分布）才失败——失败感来自"不够熟练"而非运气，契合答错仅空转基调。
- **经验曲线**：升级所需经验 `expToNext(L) = ceil(100 × L^1.3)`；胜利经验 `= 基础 30 × 难度系数 + 熟练度加成`（本场释放过的 mastered 卡每张 +5）。~~前 5 级约 1–3 场升一级，之后放缓。~~【v2.3 按实测更正，见 D35】遭遇战（系数 0.7 ⇒ 21 exp/场）下 **L1→L2 约 5 场**，L5→L6 约 10 场以上——原「1–3 场」是 Plan 2 前的估算，从未与 `expToNext` 对过账，Plan 4 终审发现后据实记录。曲线本身未改（改它会作废 T2 的 sim 基线）。
- **等级→属性**：每级 力量+2（攻）/ 体质+2（防）/ 气血+10，线性；基础值 攻10 防5 血100。
- **属性映射**：体力 = 已入脑卡数（review+mastered）、精神 = 合格自建卡数（§6.4 口径）；防御 = 基础防 + 等级×2 + floor(体力/10)，攻击 = 基础攻 + 等级×2 + floor(精神/8)。单卡伤害 = 攻击 × damageMultiplier(stability) × uniform(0.9,1.1)。
- **装配层三条口径红线（Plan 2 终审 N-1/N-2/N-3）**：① 生产代码的体力/精神一律按**全库**统计派生，禁止照抄数值模拟器的池内简化口径（会系统性压低战力）；② victoryExp 接线时传**实际释放**的卡子集，不用池内计数（提前 won 会虚高 ≤5×作废 mastered）；③ 导入旧档链路中 migrateSave 的调用时机由导入 UI 决定并显式提示用户。
- **伤害倍率与首战教学局（v2.4，Plan 5 数值改进 · 用户实测驱动，见 D39）**：`damageMultiplier` 的低两档上调为 `new 0.3 / learning 0.7`（原 0.1 / 0.5；`review 1.0 / mastered 1.5` 不动）；`DIFFICULTY` 增加 `tutorial: 0.3` 档。**根因**：每张卡分摊的敌血恒为 `BASE_CARD_DAMAGE × 系数`（遭遇战 7 点），**与池长无关**——旧值下 L1（atk=12）的 `new=1` 点、`learning=6` 点都打不穿，玩家"背过一遍回来还是输"，新手期存在数学上不可能赢的门槛。教学局只在 `meta.plays === 0` 的首战生效（敌血 30 vs 30–40 总输出 ⇒ 必胜但每击仅 3–4 点、手感是险胜），结算仍按遭遇战（kind=encounter、经验 21）。
- **装配层第四红线（v2.2，Plan 4 spec 决策 D28）**：`deriveStats` 的 `def`/`maxHp` 必须进入战斗结算——敌人伤害 `damageToPlayer = max(1, enemyPower − def) × uniform(0.9,1.1)`，每回合在玩家行动后结算（miss 回合不免除），玩家气血归零即战败；答错仅空转的红线不变（错题对敌零输出，但敌人照常出手）。敌人强度与 HP 同源但**分档封顶**：`enemyPower = ceil(BASE_CARD_DAMAGE × POWER_FACTOR[d])`，POWER_FACTOR={encounter:0.7, boss:1.1}（遭遇战 7 / Boss 11；boss 档刻意不用 HP 系数 1.5——那会让 Boss 反击 15 超过 good 档基础输出 12，击穿「全对必胜」红线；封顶到 1.1 保证全对时净输出仍为正）。HP 公式不变。性质变化如实申报：「全对必胜」收窄为「全对且够肉才必胜」（薄血号在长池可能先死，属预期压力）。
- **只读态红线（v2.2，Plan 4 spec 决策 D29）**：存档不可恢复损坏时 coordinator 进入只读闩锁（Plan 3 C-1 已实现机制），UI 必须三件套：常驻横幅「存档无法读取，本次进度不会保存」+ 坏档原文逐字节导出出口（人工抢救的最后机会）+ 写面抛 `SaveReadOnlyError` 全部捕获为可见提示，禁止静默吞掉。

| 口径 | 值 | 说明 |
|---|---|---|

| 长文处理 | 自动分块、一次掘完 | 每块 ≤4000 字符，逐块扣额度；屏上如实写"本次发了 N 次请求"，不让额度花得不明不白（D45） |

## 7. 美术方向

- **视觉主轴：水墨像素**（v2 具体化，§11 D15）。低饱和、留白、宣纸质感为底；高饱和赛博光效（青紫粉）只用于怪物与混沌相关物——"古法 vs 云端"是画面上唯一的色彩冲突。
- **定制风像素**：AI 出图辅助 + 手工修图统一到固定调色板。
- 开工前必须先产出《像素美术规范》：逻辑分辨率、整数缩放倍率、限定色板（建议 ≤32 色）、sprite 尺寸网格（16×16 / 32×32）、动画帧数标准、像素字体选型。
- **规格清单（MVP）**：侠客战斗立绘剪影 ×1 · 小怪 sprite ×4（静帧）· 卷灵 Boss 64×64 静帧 ×4 + 受击程序特效（闪烁/抖动，不做逐帧动画）· 序章静态插画 ×7–8 · 战斗背景（数据荒原）×1 · UI 元件一套。
- **音频（双轨最小配置）**：战斗 BGM（古琴+电子氛围，CC0 素材拼接或 AI 生成）+ 关键音效 ×2（出卡命中、净化成功）。
- 禁止在成品中出现非整数缩放导致的像素扭曲（这是像素风最常见的破功点）。
- UI 需支持竖屏单手操作（手机为主要载体）。
- 文案双轨制：叙事文本半文半白；功能界面保持大白话（LORE §6）。

## 10. 工程与交付（v2 新增）

- **技术栈**：Vite + TypeScript + 手写 Canvas 渲染层；无游戏引擎依赖；核心逻辑纯 TS 模块零 DOM（对齐 §1 平台约束）。状态管理用轻量 store；UI 表单类界面走 DOM 层与 Canvas 战斗层分离。
- **仓库与部署**：git 仓库根 = `pixel-flashcard-rpg/`；GitHub Actions 自动部署 GitHub Pages；`.dsh/skills` 项目级 skill 随仓库解析。
- **PWA**：SW 预缓存全部静态资源（含音频/插画），manifest 配图标与主题色，安装提示；离线可玩为 DoD3 硬指标。
  **清单必须放在 `public/`（构建后落在站点根）**，图标至少一张 **192×192**（另有 512 与 maskable）——
  这两条不是风格问题：错一处，Chrome 只会给一个"坏掉的书签"（无真应用、无分享入口），详见 D51。
  **但"能装成应用"本身不由我们决定**：安卓的安装要经过 Google 的 WebAPK 铸造服务器，到不了 Google 的网络下必然静默失败 —— 详见 D52（含替代路与实测数据）。
- **测试策略**：SRS 引擎、战斗数值、存档读写三个纯逻辑模块按 TDD 覆盖（test-driven-development skill）；UI 层人工验证；webapp-testing 留后。
- **安全评审节点**：实施计划中在「LLM 管线接入」与「发布前」各设一次 reviewing-security 检查点。
