# 知识侠客 · Plan 5/5：AI 辅建管线（玩家自带 Key）实施计划

> **For agentic workers:** 用 subagent-driven-development 逐任务实现（checkbox 追踪）。

**Goal:** 让玩家用**自己**的 API Key 调用 LLM，做三件事——把一段文字辅建成闪卡、给自建领域起卷灵称号、为自建领域写图鉴彩蛋；全程**本地直连**（无后端）、**产出视为不可信数据**（严格解析 + 人工确认后才入库）。

**Architecture:** 分层沿用 Plan 1–4 的纪律，新增三层：
- `src/core/llmParse.ts`（纯逻辑）：把模型返回的文本**严格解析**成候选数据（卡片/称号/彩蛋）。零 DOM、零网络、零时钟——因而可被判据穷举。
- `src/platform/llmConfig.ts` + `src/platform/llmHttp.ts`（平台面）：**Key 的唯一存放点**（`localStorage`）+ 唯一的网络出口（`fetch` / AbortController / 错误映射）。两者都不认识存档。
- `src/app/llmFlow.ts`（编排）：构造提示词（纯函数）→ 调注入的 `chat()` → 交 core 解析 → 回 `{ok, candidates}`。**它自己不写存档**：写入一律由 UI 在玩家确认后走既有写口。

**Spec:** `docs/PRD.md` §4.3–4.4（AI 辅建）、§6.1（纯本地）、§8（MVP 第 7 项 + D30 顺延登记）、§11 D30；`docs/LORE.md` §4.2（称号格式「{雅号}篇·卷灵」）、§5.4（彩蛋=纯阅读向短文）。

## Global Constraints

- **Key 纪律（本计划的核心安全面）**：只存 `localStorage` 的 `zx-xia.llm.v1`，**绝不进 `SaveFile`**——备份文件会被分享/拷贝，Key 进去就是泄漏。UI 不回显明文（掩码 + "已保存"标记），可一键清除。
- **数据最小化**：只发送玩家**当场粘贴/指定**的内容（那段文字、领域名与卡面），**绝不整档上传**（不含 SRS/榜单/存档元信息）。
- **产出不可信**：模型输出先过 `core/llmParse` 的严格校验（JSON 解析、字段类型、长度上限、条数上限、控制字符剥离）；渲染走 `textContent`（全仓零 innerHTML）；**任何写入都要玩家逐条确认**，绝无自动落库。
- **网络失败要说人话**：401/403/429/5xx/超时/跨域各给一句可读原因（"Key 不对"/"被限流，等一会儿"/"这家服务不允许浏览器直连"），不重试风暴、不吞异常。
- 分层守卫继续全绿：`src/core/**` 与 `src/app/**` 都不得出现 DOM/平台单例（`npm run check:purity` 已覆盖两层）。
- 门禁五段全绿才 commit：`typecheck → check:purity → test → build:only → smoke:dist`。

## Review Focus

1. **Key 会不会泄漏**：进备份？进日志？被回显？被写进 prompt？（→ 任务 1/2/4/5）
2. **模型输出能不能注入**：伪造的结构、超长字段、控制字符、HTML 片段、条数爆炸。（→ 任务 1/3）
3. **人审闸门是否真在**：取消/失败路径零写入；确认路径逐条入库且来源标 `llm`。（→ 任务 4/5/6）
4. **失败可读**：五种网络错误各一句人话，且不泄漏 Key 到错误文本。（→ 任务 2）

### Task 1: `core/llmParse` —— 不可信输出的严格解析（纯逻辑）

**Files:** Create `src/core/llmParse.ts`；Test `tests/core/llmParse.test.ts`

**Interfaces:**
```ts
export interface CardCandidate { readonly front: string; readonly back: string; readonly tags: readonly string[] }
export interface NameCandidate { readonly name: string }
export type ParseResult<T> = { ok: true; value: T[] } | { ok: false; reason: string }
export function parseCards(text: string, opts?: { max?: number }): ParseResult<CardCandidate>
export function parseNames(text: string, opts?: { max?: number }): ParseResult<NameCandidate>
export function parseEgg(text: string): { ok: true; text: string } | { ok: false; reason: string }
```
**口径：** 容忍 ```json 围栏与前后废话（用第一个 `[`/`{` 到最后一个配对括号的**扫描**而不是贪婪正则）；front/back 非空、≤200 码点、剥控制字符、去首尾空白；tags 逐项字符串、≤8 个、每个 ≤16 码点；卡候选 ≤ `max`（默认 20，超出截断并**如实申报**截断）；解析失败/结构不符/零候选一律 `{ok:false, reason}`；**永不抛**。
- [ ] Step 1 失败测试（含：围栏、前后废话、超长、控制字符、条数爆炸、空数组、非 JSON、HTML 片段、`{{__proto__}}` 之类脏键）
- [ ] Step 2 红 → Step 3 实现 → Step 4 绿 → Step 5 Commit `feat(core): strict parsing for untrusted LLM output`

### Task 2: `platform/llmConfig` + `platform/llmHttp` —— Key 存放与唯一网络出口

**Files:** Create `src/platform/llmConfig.ts`、`src/platform/llmHttp.ts`；Test `tests/platform/llmConfig.test.ts`、`tests/platform/llmHttp.test.ts`

**Interfaces:**
```ts
export interface LlmConfig { baseUrl: string; apiKey: string; model: string }
export const DEFAULT_LLM_CONFIG: LlmConfig                 // DeepSeek 预设
export const LLM_PRESETS: ReadonlyArray<{ id: string; label: string; config: LlmConfig }>
export function loadLlmConfig(): LlmConfig                 // 读 localStorage，坏值回落默认；Key 不校验格式只 trim
export function saveLlmConfig(cfg: LlmConfig): void
export function clearLlmConfig(): void
export function maskKey(key: string): string               // 'sk-abc…1234' / '' → '（未设置）'

export type ChatResult = { ok: true; text: string } | { ok: false; reason: string }
export function chat(deps: {
  config: LlmConfig;
  messages: ReadonlyArray<{ role: 'system' | 'user'; content: string }>;
  fetchImpl?: typeof fetch;
  timeoutMs?: number;
  signal?: AbortSignal;
}): Promise<ChatResult>
```
**口径：** URL = `${baseUrl.replace(/\/+$/,'')}/chat/completions`（DeepSeek 与 DashScope 兼容模式同构）；请求体 `{model, messages, temperature:0.3, stream:false}`；头 `Authorization: Bearer <key>` + `Content-Type`；**Key 不进任何错误文本**（错误映射只谈状态码与语义）；超时用 AbortController（默认 30s）；`401/403 → Key 不对或无权限`、`429 → 被限流`、`5xx → 服务端故障`、`TypeError → 连不上/可能不允许浏览器直连（跨域）`、`AbortError → 超时`；响应形状不符（无 `choices[0].message.content`）→ 明确 reason。

- [ ] Step 2 红 → Step 3 实现 → Step 4 绿 → Step 5 Commit `feat(platform): local-only LLM config and the single network exit`

## Self-Review 结论

1. **Spec coverage:** PRD §4.3–4.4 的三项 AI 职能各有一任务；Key 本地化与"人审后入库"（§4.4）由任务 4/5/6 兑现；D30 的顺延项在本计划收回。
2. **安全面**：Key 三处防线（localStorage-only / 不回显 / 机器判据）＋ 数据最小化（只发粘贴内容）＋ 输出严格解析与逐条确认。
3. **未做（如实登记）**：流式输出（`stream:false`，短文本不需要）、多轮对话、代理服务器（纯本地原则不允许）、Key 加密（浏览器里没有可信密钥，加密只是自欺）。
