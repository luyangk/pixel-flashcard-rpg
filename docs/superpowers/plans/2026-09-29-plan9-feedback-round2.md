# Plan 9：第二轮现场反馈（干扰项 / 个人纪录 / 建卡质量与看原文）

> 来源：2026-09-29 玩家三条现场反馈 + 一轮 grill-me（12 问逐条拍板）。
> 决策已登记进 `docs/PRD.md` §11 的 D56–D60（v2.15）。**本文件是施工单**，口径以 PRD 为准。

## 0. 三条反馈与根因（都是查过代码的，不是猜的）

| 反馈 | 根因（代码位置） |
|---|---|
| ①「生活常识的题配了 AI 的选项」 | `src/ui/battleScreen.ts` 的 `ensureChoices()` 把**本局池里所有卡的背面**都丢进干扰项池；`src/core/choices.ts` 的顺序是「卡上自带 → 池子 → 同领域补」。预置卡**没有自带 choices**，只能吃池子 —— 池子一混领域（多领域合练、或 AI 卡存进了同一领域）就串味 |
| ②「本地榜看不懂」 | `src/core/leaderboard.ts` 的记录是**每一局**的战绩（`(卡数−失误)×10 + 等级×5 + Boss 50`），菜单直接按分数列「生活常识 · 215 分 · 胜」——它是单局成绩，不是个人水平 |
| ③「卡片抓不住主线，还看不见原文」 | 两处**都**是真的：<br>· 内容侧：从来源库点的 arXiv 只有**摘要**（1500–2000 字，摘要里本就没有步骤/推理链）；<br>· 管线侧：`src/app/llmFlow.ts` 的 `CARD_SYSTEM` 硬性限死 **front ≤40 / back ≤80 字、一张卡只考一个知识点**，而 `src/app/knowledgeFlow.ts` 把正文**按 4000 字切块分别生成** —— 主线/因果在切块那一步就散了 |

## 1. 批次划分（玩家拍板：先快修，再重做建卡）

- **批次一（快、看得见）**：T1 干扰项 · T2 个人纪录与玩家身份 · T3 遭遇战名字 · **T4 源库读取体验（D62，玩家刚踩到的坑）**
- **批次二（重活）**：T5 两段式建卡与卡片口径改造 · T6 看原文（候选内嵌 + 卡上链接）· **T7 取全文档（D61）**

每个任务：Step 1 失败测试 → Step 2 红 → Step 3 实现 → Step 4 `npm run verify` 五段全绿 → Step 5 Commit + 推送（确认 CI/Deploy 双绿），**外加变异自检**（每条都要真的会红）。

## 批次一

### T1 干扰项：同领域取池 + 生成时锁领域 + 单卡「重出选项」（D56）

**口径**
1. **池子只取同领域**：`ensureChoices` 的干扰项来源改为**该卡的领域**（`deckId` 相同的其他卡）的背面 + 它们自带的 `choices`；**删掉"本局池里其他卡"那条**（多领域合练时它就是串味源头）。同领域凑不够 ⇒ 少给选项；一个都没有 ⇒ 回落到「看答案」并说明原因（既有行为）。
2. **生成时锁领域**：`CARD_SYSTEM` 的 `choices` 要求补一句硬约束 —— 干扰项**必须与 back 属于同一知识领域/同一主题**，不得引入其他领域的概念，且要像"常见误解"而不是"别的学科的词"。
3. **单卡「重出选项」**：练功 → 看旧卡里，每张卡（与「改」并排）多一个按钮，只重跑这张卡的干扰项。新增 `src/app/llmFlow.ts` 的 `suggestChoices({chat}, {front, back, deckName})`，复用 `core/llmParse.sanitizeChoices` 的单一消毒口径；结果经 `app/library.updateCard` 的写口落盘（要支持只改 choices）。
   - **记账**：每次「重出选项」记 **1 张卡**的额度（它是一次真实 LLM 调用，且这个按钮可连点）。屏上如实写着这一点，到顶就说"明天再来"。
   - 缺 LLM 配置 ⇒ 按钮**不显示**（不显示点了没反应的入口）。

**测试（已落地）**：`tests/ui/battleScreen.test.ts` BS#A11/A12（跨领域卡的背面不许进选项；混池里只挑同领域）、
`tests/app/llmFlow.test.ts` LC#S1–S4（prompt 契约 / 消毒 / 坏形状 / 调用失败）、`tests/ui/practice.test.ts` PR#C1–C3、
`tests/app/library.test.ts` LB#D1–D3（`setCardChoices` 只改选项、同值不重写）、
`tests/ui/hostAdapters.test.ts` AD#14/#15（**装配层**：一次调用 = 额度 -1；额度为 0 时一次模型调用都不发）。

**T1b（玩家追问"看旧卡里如何看到选项是什么呀"后补的洞）**：干扰项以前**根本不显示**，
于是「重出选项」是个"看不见对象"的按钮。现在两处都露出来：
- **练功·看旧卡**：卡行多一行 `选项：A / B / C`；没有就写「选项：无（战斗里会用同领域其他卡补）」（PR#D1–D3）；
- **采新卡·候选审阅**：候选行同样列出模型给的选项（PC#12）—— 不搭就在"存之前"拦住，而不是进了战斗才返工；
- 文案由**同一个函数**（`practiceCollect.choicesLineOf`）产出，两处不许各写一份（迟早分叉）。
- 变异自检 3 条全部会红（不显示 / 条件写反 / 只列第一条）。

**T1c（玩家确认根因后追加）：30 张预置卡自带 90 条干扰项 + 老档回填**。
玩家实测确认："预置知识没有通过大模型生成选项，都为空，所以战斗补充的时候同领域答案凑不齐"。
- 内容侧：`assets/content/preset.json` 里 30 张卡各补 **3 条同领域、像常见误解**的干扰项
  （逐条自检：不重复、不等于答案、每条 ≤30 字；`PC#3c` 机器化守住这四条）；
- 加载侧：`PresetCardContent.choices` + `validateContent` 形状校验（空白/非字符串/超条数/超长一律整份拒）
  + `buildPresetEntities` 经 `sanitizeChoices` 带进卡（`PC#3d` 守住"加载器漏传"）；
- **老档回填** `backfillPresetChoices`：预置内容只在**空库首灌**时进档，老玩家的 30 张卡永远没有选项 ——
  所以启动时跑一遍"只补缺"的回填（只认 `source.type === 'preset'` + 现在无选项；一次批量写；
  没有要补的就不碰存档）。PC#6–#8 与 PC#7b 钉住它；变异自检 3 条会红（覆盖玩家重出 / 只认 id 不认来源 / 加载器漏传）。

**已落地（commit 见 git log）**：+12 用例；`src/ui/battleScreen.ts` 池子改同领域、`src/core/llmParse.ts` 新增
`parseChoices`、`src/app/llmFlow.ts` prompt 锁领域 + `suggestChoices`、`src/app/library.ts` 新增 `setCardChoices`、
`src/ui/practice.ts` 与 `src/ui/hostAdapters.ts` 接线（含 1 张卡额度记账）。

**变异**：① 池子仍吃全池；② prompt 去掉领域锁；③ 重出选项不记账；④ 缺 LLM 口也显示按钮；
⑤ 重出时把答案本身收进干扰项；⑥ `setCardChoices` 顺手改了背面 —— **6 条全部会红（已跑）**。

### T2 个人纪录 + 玩家身份（D57）

**口径**
1. **菜单保留现有榜单**（每局战绩），**新增**一个「个人纪录」区块，四个维度（**都用现有存档现算，不新增历史字段**）：
   - 等级 / 经验（`settings.progress`）；
   - 已掌握的卡数（`srs.stability === 'mastered'`）；
   - 自建卡数（`source.type ∈ {manual, llm, hotspot}`）；
   - 有效复习天数（`core/reviewLedger` 的账本）+ **最长连续天数**。
2. **最长连续**需要落一个数：`progress.bestStreak`（可选位 + `validateSave` 在场严检 + `migrateSave` 补 0），在结算/复习落账时更新（当前连续 ≥ bestStreak 就刷新）。
3. **玩家身份（本地）**：存档里 `settings.profile = { nickname, userId }`（可选位，三段式；昵称默认「无名侠客」、`userId` 由 app 层在首次挂载时用注入的时钟+随机源生成短 ID 并落盘）。
   - 设置里可改昵称（≤12 字）；`userId` 只显示不可改（将来交换战绩时的标识）。
   - **本轮不做跨人对比**（玩家拍板：社交等单机打磨完再说；将来也只排"等级"这类汇总信息，不排战绩）。

**测试（已落地）**：`tests/app/records.test.ts` RC#1–#4（四个维度 / 复习天数取并集 / 连续天数的今天与昨天边界 / 脏数据不崩）、
`tests/ui/menu.test.ts` MN#R1–#4（四维渲染 + 旧榜不动 + 昵称进说明）、
`tests/platform/profileStore.test.ts` PF#1–#5（截断 / 净化 / ID 只生成一次 / 存储不可用 / 不碰 Key）、
`tests/ui/settings.update.test.ts` SU#P1–P3（改昵称带住 ID）、`tests/ui/host.test.ts` HS#R1–R2（装配层透传）。

**两处设计修正（实测驱动，写回 PRD D57）**：
1. `progress.bestStreak` **不加字段** —— 加它当场红了 6 条"逐键无损往返"用例（SM#3a/BK#2/BK#4/BK#5b/BK#26/PC#3）；
   改成**从账本现算**（窗口 400 天内的最长），代价只是"一年前的旧纪录"不再保留；
2. 昵称/ID **不进存档、存本机**（第四个 `localStorage` 归属，LS#3 白名单已登记）——
   它不是游戏进度，且该活过「重置存档」（与 AI Key 同款口径）；加进存档同样要付上面那笔夹具/迁移的账。

**变异自检（6 条全部会红）**：① 自建卡把预置也算进去；② 复习天数只看第一张卡；③ 连续天数只认"今天"；
④ `ensureProfile` 每次都生成新 ID；⑤ 菜单漏透传 `now`（连续天数永远 0）；⑥ 改昵称时把 ID 写丢。

**变异**：① 自建卡把预置也算进去；② 连续天数不判"跨天中断"；③ 昵称空串也存；④ 纪录区块把每局战绩当个人最好。

### T3 遭遇战名字（D58）

**口径**
1. **时机**：**结算时**生成（玩家拍板：不阻塞开局），只在**结算屏 + 战绩记录**里出现。
2. **形态**：`雅号 · 领域组合`，例：`长安夜雨 · 唐诗 × 成语典故`、`三域合参 · 生活常识 / 唐诗 / AI-Agent`。雅号 ≤6 字，整名 ≤24 字。
3. **LLM + 兜底**：`suggestFightTitle({chat}, {domains, kind})` 走一次最小调用（prompt 在 `app/llmFlow.ts`，与称号/彩蛋同款）；
   **没配 LLM、调用失败或超时 ⇒ 本地确定性词表兜底**（按领域组合的名字派生索引取词，同一组合必得同一个雅号），保证不配 LLM 的玩家也看得到名字。
4. **落盘**：`RunRecord.title?`（可选位；旧记录没有 ⇒ 菜单回落到「领域组合」摘要，不再只写一个领域名）。
5. **记账**：一次结算一次调用，不占卡片额度（不成 Button、不可连点）。

**测试**：`tests/app/llmFlow.test.ts`（标题 prompt 与解析、非法输出回落）、`tests/core/leaderboard.test.ts`（`title` 可选位的排名不受影响）、`tests/app/results.test.ts`（有/无 LLM 两条路都写进记录）、`tests/ui/menu.test.ts` + `result.test.ts`（显示名字与回落）。

**测试（已落地）**：`tests/app/fightTitle.test.ts` FT#1–#6（组合形态 / 兜底确定性 / 不同组合不同雅号 /
长度上限 / 取模型雅号时剃掉标点 / `splitCombo`）、`tests/app/results.test.ts` RS#T1–T2（记录带名字、升级保留组合）、
`tests/ui/result.test.ts` RS#N1–N3（显示名字、**只请一次**、练功不请求）、`tests/ui/menu.test.ts` MN#T1–T2（榜单行用名字，老记录回落领域名）。

**实现的取舍（比计划更稳的两处）**：
1. **兜底名在结算时立刻写进记录**（本地、确定性、离线可用），LLM 只在**有 Key 且有空**时**异步升级**
   —— AI 永远不挡在结算路径上（D38 的口径），玩家不会为了一个名字多等一秒；
2. **模型只给雅号，组合由我们自己拼**：让模型连领域名一起写，它就有机会写错/漏掉某个领域，
   而那是玩家一眼能看出的错（`composeTitle(yahao, names)`）。
   升级时组合从旧名字里拆回来（`splitCombo`，我们自己的格式）。

**变异自检（6 条全部会红）**：① 兜底雅号改随机（记录会飘）；② 组合只写第一个领域（回到现场那个问题）；
③ 记录不带名字；④ 升级时丢掉组合；⑤ 结果屏每次渲染都请求命名（反复花钱）；⑥ 榜单行无视名字。

## 批次二

### T4 两段式建卡 + 卡片口径改造（D59）

**口径**
1. **两段式（按长度阈值）**：正文 ≥ **1500 字**时先产出**提纲**（主线 / 关键步骤 / 因果链 / 易混点），再按提纲出卡；短文本（<1500 字，含你自己粘的短笔记）仍**一次到位**。
   - 提纲调用**不产卡 ⇒ 不占卡片额度**，但要计入 `CollectResult.requests` 并在屏上如实显示进度（"正在提炼主线…" → "正在出卡…"）。
2. **卡片口径改造**（`CARD_SYSTEM`）：
   - `back` 上限 80 → **160 字**，`front` 40 → **60 字**，明确允许"一张卡承载一条链路/多个要点"；
   - **禁止元信息卡**：不得把日期、作者、期刊、来源、"本文提出"这类信息做成卡（玩家原话：卡片都是关注记忆来源日期之类的信息）；
   - **优先级**：先抽可迁移的主线、步骤、因果与判断依据；细枝末节宁可少出。
3. **不破坏既有契约**：`CHOICES_MAX`/`CHOICE_TEXT_MAX`/`front` 的卡面渲染与既有测试的口径一并更新（卡面变长 ⇒ 战斗屏卡片区要能容纳，必要时给最大高度 + 滚动）。

**测试（已落地）**：`tests/app/knowledgeFlow.test.ts` KF#O1–O5（长文两次调用 / 短文一次 / 进度回调有序 /
提纲失败回落分块 / 提纲 prompt 契约）、`tests/app/llmFlow.test.ts` LC#C1–C4（禁元信息卡 / 60·160 上限 /
"一条链路" / 提纲模式的说明）、`tests/ui/practice.collect.test.ts` PC#13（屏上依次报两个阶段）。

**样例（给玩家判方向用）**：`docs/samples/card-spec-d59.md` —— 真材料 + 逐字 prompt + 我手写的输出对比
（明说不是真模型输出：我没有玩家的 Key）。
**【2026-09-29 玩家裁定】步骤卡与易混卡就按现口径** ⇒ prompt 不再调整（样例文档里那两个问题已有答案）。

**变异自检（7 条全部会红）**：① 长文也直接分块出卡；② 短文本也跑两段；③ 提纲失败就不生成；
④ 出卡那次不带"这是骨架"；⑤ 去掉"禁元信息卡"；⑥ 长度上限改回 80；⑦ UI 不报进度。

**变异**：① 阈值失效（短文也跑两段）；② 提纲调用吃掉卡片额度；③ prompt 去掉"禁元信息卡"；④ 长度上限改了但解析侧没改（长答案被静默截断）。

### T5 看原文：候选内嵌 + 卡上链接（D60）

**口径**
1. **候选取证（采新卡）**：每条候选卡旁一个「看原文」开关 —— **手里已有正文**（源库的摘要、GitHub 更新说明、你粘的正文）就**就地内嵌**；没有的给「打开原文去复制」。目的：勾选前能对照，判断 LLM 总结得对不对。
2. **卡上（看旧卡 / 复习）**：`SourceInfo.url` 存在时，卡行多一个「看原文」；没有链接就不显示（不显示点了没反应的入口）。
3. **隐私**：内嵌只用**本机已有**的正文；要联网取原文时仍走既有口径（可选读取服务、链接会外发的那笔账照旧写明）。

**测试（已落地）**：`tests/ui/practice.collect.test.ts` PC#14–#16（有正文内嵌 / 被拦不做假面板 / **面板跟着新批次走**）、
`tests/ui/practice.test.ts` PR#S1–S2（有链接才显示、点了打开的是**那张卡的**链接）。

**实现上的一处简化（与原计划的偏差，说明理由）**：原计划写"**每条候选**可展开原文"，
但一批候选来自**同一份资料** —— 逐条重复同一段正文只会更乱。所以做成**候选区共享一块面板**
（`cand-source`），一批一次；内容跟着新批次走（PC#16 钉住张冠李戴）。

**变异自检**：① 不动（等价）② 面板内容不跟新批次（张冠李戴）③ 没链接也显示「看原文」
④ 打开的链接写死 —— 其中 ②③④ 会红；①"没有正文也显示开关"是**等价变异**
（有候选必有正文是生成路径的不变量，UI 上走不到那个状态），如实登记。

**变异**：① 无 url 也显示按钮；② 内嵌显示的不是当次原文（张冠李戴）；③ 内嵌绕过 openUrl 注入、测试无从取证。

### 附加问 1：除了摘要，要不要再把全文加进来？（D61）

**结论：要，但做成"按需的第二档"，而且**默认仍走摘要**。理由与做法：

- 摘要（arXiv 1500–2000 字）本来就装不下主线/步骤 —— 这正是"卡片抓不住主线"的一半原因（D59）。要出真正的"流程卡/因果卡"，必须有全文；
- 但全文很贵：一篇论文正文几万字，走读取服务还要先把它取回来。所以**不能让每次出卡都默默升级成全文**；
- 口径：
  1. 论文类来源的条目上多一个 **「取全文再出卡」**：经读取服务取 **HTML 版**（`arxiv.org/html/<id>`，有 HTML 版就用；否则取来源页），取不到就维持摘要并如实说明；
  2. **提纲的输入策略**（关键，控制 token）：全文按**小标题**切分 → 每节取前 ~600 字 + 全篇首尾各 2000 字 ⇒ 覆盖全篇结构但长度可控；全文上限 60k 字，超出截断并告知；
  3. **候选卡上标明依据级别**（「据摘要」/「据全文」）—— 直接服务于你那句"不然无法判断 llm 总结的内容对不对"；
  4. 没有读取服务 ⇒ **只给「打开原文去复制」**，不假装能取全文；
  5. 记账：取全文 = 1 次读取服务调用；提纲 + 出卡 = 2 次 LLM 调用（提纲不占卡片额度）。屏上如实显示每一步。

### 附加问 2：第一个「需读取服务」的源读完了，其余的都没完成 —— 有限时吗？（D62）

**有，而且不止一个。实测与代码三层都查了：**

1. **网络层（最可能的主因，且是你那边可控的）**：读取服务多半在境外。刚才同一域名 `r.jina.ai`
   几分钟前还是 **200 / 0.6s**，随后两次 DNS 查询分别给出 `2a03:2880:…:face:b00c…` 与 `2001::c73b:946a`
   —— **两个都不是它的真实地址**，`TCP 443` 直接不通。这是典型的 **DNS 干扰**特征。
   也就是说：**它通是因为你的代理开着；代理一断，读取服务立刻全灭** —— "第一个成功、其余全灭"正好发生在这个切换点上。
2. **我的实现缺陷（无论网络怎样都该修）**：
   - `busy` 守卫**静默吞点击**：上一个源还在读时，点别的源**没有任何反应**（既不提示也不能取消）⇒ 看起来就是"未完成"；
   - `direct:false` 的源**串行跑两次**（读取服务 15s + 直连 15s）= 最长 **30 秒**卡住，这期间所有点击被吞；
   - 体积上限 3MB **整份判失败**：arXiv 的日报渲染后实测 2.6–2.7MB，`cs.AI`（331 条）必然踩线；
   - **没有缓存**：同一个源反复点，反复烧钱。
3. **计费层**：读取服务按内容量计费（以它的文档为准；本次网络下其域名已不可达，无法复核细节）。
   一份 2.6MB 的渲染内容**很贵** —— 免费额度很可能一两次就吃光，这与"第一个之后全不行"高度吻合。

**改法（写进 T4）：**
- **小端点优先**：源库里每个源可带一个"走读取服务时用的小端点"。arXiv 这类"日报"改用它的查询 API
  （`export.arxiv.org/api/query?…&max_results=20`，**实测只有 13KB**），而不是一天 300+ 条的 RSS；
- **只读前 N 条就够**：RSS 与渲染列表**截断解析**（前 512KB 足以凑够 20 条），不再为整份 2.6MB 买单；
  JSON 仍需完整解析（截断会毁掉 JSON），但上限提到 8MB 以免整份失败；
- **busy 如实反馈 + 可取消**：状态行写「上一个源还在读…」并给「取消」，按钮禁用并显示正在读哪个源；
- **超时预算与省一半**：读取服务 25s；`direct:false` 的源在读取服务失败后**不再白跑直连**；
- **会话内缓存**：同一源一次会话只读一次，重复点击直接用缓存；
- **文案**：读不到时提示"读取服务多半在境外，先确认代理还在"；设置页读取服务旁写明"按内容量计费，大源一次可能很贵"。
