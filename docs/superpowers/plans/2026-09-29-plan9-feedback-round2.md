# Plan 9：第二轮现场反馈（干扰项 / 个人纪录 / 建卡质量与看原文）

> 来源：2026-09-29 玩家三条现场反馈 + 一轮 grill-me（12 问逐条拍板）。
> 决策已登记进 `docs/PRD.md` §11 的 D56–D60（v2.15）。**本文件是施工单**，口径以 PRD 为准。

## 0. 三条反馈与根因（都是查过代码的，不是猜的）

| 反馈 | 根因（代码位置） |
|---|---|
| ①「生活常识的题配了 AI 的选项」 | `src/ui/battleScreen.ts` 的 `ensureChoices()` 把**本局池里所有卡的背面**都丢进干扰项池；`src/core/choices.ts` 的顺序是「卡上自带 → 池子 → 同领域补」。预置卡**没有自带 choices**，只能吃池子 —— 池子一混领域（多领域合练、或 AI 卡存进了同一领域）就串味 |
| ②「本地榜看不懂」 | `src/core/leaderboard.ts` 的记录是**每一局**的战绩（`(卡数−失误)×10 + 等级×5 + Boss 50`），菜单直接按分数列「生活常识 · 215 分 · 胜」——它是单局成绩，不是个人水平 |
| ③「卡片抓不住主线，还看不见原文」 | 两处**都**是真的：<br>· 内容侧：从来源库点的 arXiv 只有**摘要**（1500–2000 字，摘要里本就没有步骤/推理链）；<br>· 管线侧：`src/app/llmFlow.ts` 的 `CARD_SYSTEM` 硬性限死 **front ≤40 / back ≤80 字、一张卡只考一个知识点**，而 `src/app/knowledgeFlow.ts` 把正文**按 4000 字切块分别生成** —— 主线/因果在切块那一步就散了 |

## 1. 批次划分（玩家拍板：先快修，再重做建卡）

- **批次一（快、看得见）**：T1 干扰项 · T2 个人纪录与玩家身份 · T3 遭遇战名字
- **批次二（重活）**：T4 两段式建卡与卡片口径改造 · T5 看原文（候选内嵌 + 卡上链接）

每个任务：Step 1 失败测试 → Step 2 红 → Step 3 实现 → Step 4 `npm run verify` 五段全绿 → Step 5 Commit + 推送（确认 CI/Deploy 双绿），**外加变异自检**（每条都要真的会红）。

## 批次一

### T1 干扰项：同领域取池 + 生成时锁领域 + 单卡「重出选项」（D56）

**口径**
1. **池子只取同领域**：`ensureChoices` 的干扰项来源改为**该卡的领域**（`deckId` 相同的其他卡）的背面 + 它们自带的 `choices`；**删掉"本局池里其他卡"那条**（多领域合练时它就是串味源头）。同领域凑不够 ⇒ 少给选项；一个都没有 ⇒ 回落到「看答案」并说明原因（既有行为）。
2. **生成时锁领域**：`CARD_SYSTEM` 的 `choices` 要求补一句硬约束 —— 干扰项**必须与 back 属于同一知识领域/同一主题**，不得引入其他领域的概念，且要像"常见误解"而不是"别的学科的词"。
3. **单卡「重出选项」**：练功 → 看旧卡里，每张卡（与「改」并排）多一个按钮，只重跑这张卡的干扰项。新增 `src/app/llmFlow.ts` 的 `suggestChoices({chat}, {front, back, deckName})`，复用 `core/llmParse.sanitizeChoices` 的单一消毒口径；结果经 `app/library.updateCard` 的写口落盘（要支持只改 choices）。
   - **记账**：每次「重出选项」记 **1 张卡**的额度（它是一次真实 LLM 调用，且这个按钮可连点）。屏上如实写着这一点，到顶就说"明天再来"。
   - 缺 LLM 配置 ⇒ 按钮**不显示**（不显示点了没反应的入口）。

**测试**：`tests/ui/battleScreen.test.ts`（BC#? 混合池里只取同领域；同领域不足 ⇒ 少给/回落）、`tests/app/llmFlow.test.ts`（LC#? prompt 里含领域锁；`suggestChoices` 解析与消毒）、`tests/ui/practice.test.ts`（PR#? 「重出选项」缺 LLM 口不显示 / 点了调写口 / 记账 +1）、`tests/app/library.test.ts`（只改 choices 的写口不破坏其它字段）。

**变异**：① 池子仍吃全池；② prompt 去掉领域锁；③ 重出选项不记账；④ 缺 LLM 口也显示按钮。

### T2 个人纪录 + 玩家身份（D57）

**口径**
1. **菜单保留现有榜单**（每局战绩），**新增**一个「个人纪录」区块，四个维度（**都用现有存档现算，不新增历史字段**）：
   - 等级 / 经验（`settings.progress`）；
   - 已掌握的卡数（`srs.stability === 'mastered'`）；
   - 自建卡数（`source.type ∈ {manual, llm, hotspot}`）；
   - 有效复习天数（`core/reviewLedger` 的账本）+ **最长连续天数**。
2. **最长连续**需要落一个数：`progress.bestStreak`（可选位 + `validateSave` 在场严检 + `migrateSave` 补 0），在结算/复习落账时更新（当前连续 ≥ bestStreak 就刷新）。
3. **玩家身份（本地）**：存档里 `settings.profile = { nickname, userId }`（可选位，三段式；昵称默认「无名侠客」、`userId` 由 app 层在首次挂载时用注入的时钟+随机源生成短 ID 并落盘）。
   - 设置里可改昵称（≤12 字）；`userId` 只显示不可改（将来交换战绩时的标识）。
   - **本轮不做跨人对比**（玩家拍板：社交等单机打磨完再说；将来也只排"等级"这类汇总信息，不排战绩）。

**测试**：`tests/core/recordStats.test.ts`（新纯函数：四个维度 + 连续天数）、`tests/app/*`（profile 落盘与迁移）、`tests/ui/menu.test.ts`（纪录区块渲染 + 旧榜不动）、`tests/ui/settings*.test.ts`（改昵称写口）。

**变异**：① 自建卡把预置也算进去；② 连续天数不判"跨天中断"；③ 昵称空串也存；④ 纪录区块把每局战绩当个人最好。

### T3 遭遇战名字（D58）

**口径**
1. **时机**：**结算时**生成（玩家拍板：不阻塞开局），只在**结算屏 + 战绩记录**里出现。
2. **形态**：`雅号 · 领域组合`，例：`长安夜雨 · 唐诗 × 成语典故`、`三域合参 · 生活常识 / 唐诗 / AI-Agent`。雅号 ≤6 字，整名 ≤24 字。
3. **LLM + 兜底**：`suggestFightTitle({chat}, {domains, kind})` 走一次最小调用（prompt 在 `app/llmFlow.ts`，与称号/彩蛋同款）；
   **没配 LLM、调用失败或超时 ⇒ 本地确定性词表兜底**（按领域组合的名字派生索引取词，同一组合必得同一个雅号），保证不配 LLM 的玩家也看得到名字。
4. **落盘**：`RunRecord.title?`（可选位；旧记录没有 ⇒ 菜单回落到「领域组合」摘要，不再只写一个领域名）。
5. **记账**：一次结算一次调用，不占卡片额度（不成 Button、不可连点）。

**测试**：`tests/app/llmFlow.test.ts`（标题 prompt 与解析、非法输出回落）、`tests/core/leaderboard.test.ts`（`title` 可选位的排名不受影响）、`tests/app/results.test.ts`（有/无 LLM 两条路都写进记录）、`tests/ui/menu.test.ts` + `result.test.ts`（显示名字与回落）。

**变异**：① 没配 LLM 就不生成任何名字（兜底缺失）；② 名字超过长度上限不截断；③ 兜底每次给不同的名字（不确定 ⇒ 记录会飘）。

## 批次二

### T4 两段式建卡 + 卡片口径改造（D59）

**口径**
1. **两段式（按长度阈值）**：正文 ≥ **1500 字**时先产出**提纲**（主线 / 关键步骤 / 因果链 / 易混点），再按提纲出卡；短文本（<1500 字，含你自己粘的短笔记）仍**一次到位**。
   - 提纲调用**不产卡 ⇒ 不占卡片额度**，但要计入 `CollectResult.requests` 并在屏上如实显示进度（"正在提炼主线…" → "正在出卡…"）。
2. **卡片口径改造**（`CARD_SYSTEM`）：
   - `back` 上限 80 → **160 字**，`front` 40 → **60 字**，明确允许"一张卡承载一条链路/多个要点"；
   - **禁止元信息卡**：不得把日期、作者、期刊、来源、"本文提出"这类信息做成卡（玩家原话：卡片都是关注记忆来源日期之类的信息）；
   - **优先级**：先抽可迁移的主线、步骤、因果与判断依据；细枝末节宁可少出。
3. **不破坏既有契约**：`CHOICES_MAX`/`CHOICE_TEXT_MAX`/`front` 的卡面渲染与既有测试的口径一并更新（卡面变长 ⇒ 战斗屏卡片区要能容纳，必要时给最大高度 + 滚动）。

**测试**：`tests/app/llmFlow.test.ts`（阈值分流：长文两次调用、短文一次；提纲 prompt 契约）、`tests/app/knowledgeFlow.test.ts`（分块 + 提纲 + 额度账不变）、`tests/core/llmParse.test.ts`（新长度上限的截断）、`tests/ui/battleScreen.test.ts`（长 back 的渲染不溢出）。

**变异**：① 阈值失效（短文也跑两段）；② 提纲调用吃掉卡片额度；③ prompt 去掉"禁元信息卡"；④ 长度上限改了但解析侧没改（长答案被静默截断）。

### T5 看原文：候选内嵌 + 卡上链接（D60）

**口径**
1. **候选取证（采新卡）**：每条候选卡旁一个「看原文」开关 —— **手里已有正文**（源库的摘要、GitHub 更新说明、你粘的正文）就**就地内嵌**；没有的给「打开原文去复制」。目的：勾选前能对照，判断 LLM 总结得对不对。
2. **卡上（看旧卡 / 复习）**：`SourceInfo.url` 存在时，卡行多一个「看原文」；没有链接就不显示（不显示点了没反应的入口）。
3. **隐私**：内嵌只用**本机已有**的正文；要联网取原文时仍走既有口径（可选读取服务、链接会外发的那笔账照旧写明）。

**测试**：`tests/ui/practice.collect.test.ts`（有正文 ⇒ 内嵌且内容正确；无正文 ⇒ 只给按钮）、`tests/ui/practice.test.ts`（有 url 才显示「看原文」，`openUrl` 被调到）、真产物 `tests/e2e/dist.boot.test.ts` 补一条（DB#12）。

**变异**：① 无 url 也显示按钮；② 内嵌显示的不是当次原文（张冠李戴）；③ 内嵌绕过 openUrl 注入、测试无从取证。

## 2. 交付顺序与验收

1. 批次一三任务各一个 commit + 推送，每个都跑 `npm run verify`（当前基线：**87 文件 / 1270 用例** + 11 条真产物冒烟）；
2. README 的功能表与证据表、`docs/PRD.md` 的 v2.15 说明同步更新；
3. 批次一上线后，请玩家在真机上看三件事：选择题选项是否还在串领域 / 菜单里个人纪录读得懂吗 / 结算屏的遭遇战名字；
4. 批次二开工前先把 T4 的 prompt 试跑样例贴出来给玩家过一眼（"卡片是否抓到了主线"这件事只有他能判）。
