# 知识侠客 · Plan 7：练功入口 + 木桩练功（新战斗形态）实施计划

> **For agentic workers:** 由本会话按 executing-plans 逐任务实现（checkbox 追踪）；最后统一终审。

**Goal:** 菜单里出现「练功」；进去能按领域浏览卡片、**勾选要练的卡**（默认勾"到期 + 新卡"，池 ≤25），进一局**木桩练功**：敌人是木人桩（**耐久不降、不反击**）、**不判胜负**，打完池子就结算"练功完成：N 张"，给**遭遇战经验的 1/20**（≈1 点/局），**不进榜单、不计 plays、不进"有效复习日"**（推不动卷灵达标），但**卡的 SRS 照常更新**。

**Architecture:** core 只加一个**明确的战斗形态**，不靠"胜负特判"糊：
- `src/core/battle.ts`：`BattleState.mode: 'fight' | 'drill'` + 新终局 `phase:'cleared'`。drill 下**不扣敌血、不结算反击**，池尽即 `cleared`。
- `src/core/reviewFlow.ts`：`applyReview` 增"这次不计 Boss 日账"开关（drill 传 false）。
- `src/app`：`startFight` 支持**显式卡池**（勾选结果）与 `mode:'drill'`；结算走 drill 分支（经验 1/20、不写榜单、不增 plays、不抽战报碎片、不演假记忆）。
- `src/ui/practice.ts`（本计划只做骨架 + 看旧卡 + 勾选 + 练这一域；采新卡/待读清单/就地编辑留给 Plan 8）、`src/ui/battleScreen.ts`（木桩形态）、`src/ui/result.ts`（练功结算）。
- 美术：`assets/sprites/drill-dummy.png`（扩 `scripts/gen-sprites.mjs`，保持幂等 + `--check`）。

**Spec:** `docs/PRD.md` §4.5（练功模块）、§9（练功屏、战斗屏作答区）、§11 D44/D46；作答区本身由 Plan 6 交付。

## Global Constraints

- **不判胜负**：drill 的终局是 `cleared`，**不是** `won`/`lost`。不得复用 `won` 糊过去（木桩血不降 ⇒ 既有判定会给出 `lost` ⇒ 误触发败局演出）——Plan 6 的作答区（选择题/问答/看答案）在 drill 里完全复用。
- **不进有效复习日**：`effectiveReviewDays` 是卷灵达标账本，drill 一律不写它（否则木桩成了零风险刷 Boss 的捷径）。**SRS 其余字段照常更新**（练了就是练了）。
- **经验 1/20**：`max(1, round(遭遇战经验 / 20))`（≈1 点/局），并**不写榜单、不增 `meta.plays`**；drill 也不参与"首战教学局"的自动选档（`meta.plays === 0` 时 drill 仍是普通参数）。
- **池 ≤25**：与既有 `bossFightParams` 同口径；勾选为空 ⇒ 不允许开练（屏上说明），不静默给全领域。
- **美术可复现**：木人桩必须由 `scripts/gen-sprites.mjs` 生成（`node scripts/gen-sprites.mjs --check` 通过），不手搓二进制。
- 分层守卫全绿；门禁五段全绿才 commit。

## Review Focus

1. **"练功"会不会被判成输**：`cleared` 之后不能出现败局文案、假记忆演出、榜单记录、`plays+1`（→ 任务 2/5）。
2. **SRS 与 Boss 账本的分叉**：drill 后 `effectiveReviewDays` **一条都不加**，而 `ease/interval/reps/stability` 该动就动（→ 任务 2）。
3. **勾选池的边界**：空选、全选、只选未到期、勾了别人领域的卡 id、卡在开练前被删（→ 任务 2/6）。
4. **木桩形态的视觉诚实**：耐久条不降、不出现"敌人受伤"的误导（闪白/抖动语义）、没有反击飘字；缺 `dummy` 精灵时不能崩（→ 任务 3/5）。
5. **老路径不受影响**：正常遭遇战/Boss 战/教学局的判定、结算、榜单、经验一字不变（既有 900+ 用例全绿）（→ 任务 1/2）。
