# Plan 10 · 进度说明（D63）——"我现在到哪了、还差多少、什么时候能打卷灵"

> 玩家原话（2026-09-30）："对于卡的初识、已掌握等需要一些说明，现在我光看 app 无法理解这些状态，
> 也无法理解当前进度，后续差多少，类似的困惑还体现在升级经验，什么时候能打卷灵之类的问题上，
> 需要一些进度说明才更有目标感更有动力。"

## 0. 现状（查过代码，不是猜的）

| 玩家看到的东西 | 现在的样子 | 缺什么 |
|---|---|---|
| 卡片状态 | 练功·看旧卡里一行「初识 / 复习 / 已掌握」（`practice.stabilityLabel`），战斗屏有「初识」提示 | **没有解释**每个词是什么意思、**怎么才能升级**、这张卡**还差多少** |
| 等级 / 经验 | 菜单六维里一个「等级」，个人纪录里「L3 · 240 经验」 | **距下一级还差多少**、**一局大概给多少经验**、**大概还要打几局** |
| 卷灵 | 卡组行有「待复习 N / 已掌握 M」，备战能选难度 | **本领域有效复习 X / 阈值 Y**、**还差几次**，以及"**隔天练才算一次**"这条最容易误解的规则 |
| 复习天数 | 个人纪录里有「复习天数 · 连续 N 天」 | 已够用；只补一句"下一个里程碑"的余地 |

**口径全部来自既有 core 函数**（不新造数字，避免"说明"与真实规则漂移）：
- 稳定度：`core/sm2.promoteStability` —— `interval ≥ 7` ⇒ **已掌握**；`reps ≥ 1 且 interval ≥ 1` ⇒ **复习**；否则**在学**；没答过是**初识**；
- 经验：`core/stats.expToNext(L) = ceil(100 × L^1.3)`，累计消费（`applyExp`）；
- 胜利经验：`victoryExp = round(30 × 难度系数 + 5 × 参战已掌握数)`，难度系数 `tutorial 0.3 / encounter 0.7 / boss 1.5`；
- 卷灵：`core/reviewLedger.bossReady = domainReviewCount ≥ 阈值(15|30|50)`，而 `domainReviewCount` 累加的是每张卡的
  `effectiveReviewDays`（**按天**：同一张卡同一天练十次只算一次，跨过本地午夜再练才算第二次）。

## 1. 决策

**D63 进度说明**（四处，都是"就地一句话 + 一个统一口径的纯函数"）：
1. **卡片状态说清**：练功·看旧卡里每张卡的状态行补"**还差什么**"（例：「在学 · 间隔 1 天 → 7 天算已掌握」）；
   同一屏顶部放一段可折叠的《状态怎么升》，一次讲清四档与晋升条件；
2. **等级进度**：菜单个人纪录的「等级 / 经验」补「距 L{n+1} 还差 X 经验 · 打一场约 N 经验（约 M 场）」；
3. **卷灵进度**：卡组行与备战入口显示「本领域有效复习 X / Y，还差 Z 次」，达标显示「**卷灵已就绪**」，
   并始终带一句「隔天练同一批卡才算新的一次」；
4. **不算新数**：以上全部由 `core` 的既有函数派生（新增的只有"求和/求差"这类纯函数），
   UI 不自己写业务口径（避免说明与规则各说一套）。

**刻意不做**：不加入"每日任务/成就系统"这类新机制（玩家要的是**看懂**现有进度，不是又一套要追的东西）；
不做跨人对比（D57 已裁定）。

## 2. 任务

- **T1 core 派生（纯函数 + 测试）**：`expToLevelTotal(level)`（到某级**累计**需要多少经验）、
  `expGapToNextLevel(level, exp)`（还差多少）、`bossProgress(deckCards, threshold)`（X / Y / 还差 Z / ready）、
  `cardStatusHint(card)`（状态 + 还差什么的大白话）。全部零 DOM、零时钟。
- **T2 看旧卡**：每张卡状态行带上"还差什么"；屏顶《状态怎么升》折叠说明。
- **T3 卷灵进度**：卡组行 + 备战入口显示 X/Y 与"还差 Z 次"，达标显示"卷灵已就绪"。
- **T4 菜单**：个人纪录的等级行补"距 L{n+1} 还差 X 经验 · 约 M 场"。
- **T5 docs**：PRD D63、README 行、本计划的落地记录。

## 3. 验收

- 玩家只看屏（不查文档）能回答三个问题：**这张卡离"已掌握"还差什么**、**离升级还差多少**、**离卷灵还差几次**；
- 每处说明都能在代码里指到**同一个** core 口径（说明与规则不许各写一份）；
- 变异自检：把任一处说明改成"编的数字/与 core 不一致"，对应用例必须红。
